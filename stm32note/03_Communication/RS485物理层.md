# RS485 物理层

> 能力定位：在 UART 字节流外增加差分、半双工和方向控制能力。
>
> 原始来源：[[15_RS485与CAN]]。

## 组成

STM32 仍使用 UART/USART；外部 RS485 收发器把单端逻辑信号转换为 A/B 差分信号。RS485 主要定义物理层，不自动提供地址、命令和校验协议。

## 半双工方向

```text
默认接收
-> DE/RE 切发送
-> UART 发送
-> 等待真正发送完成
-> DE/RE 切回接收
```

## 总线要点

- A/B 极性和命名可能因模块而异，应看原理图或波形。
- 长线和高速通信需要合理的终端电阻、偏置和总线拓扑。
- 多节点需要统一波特率和应用协议。
- 共地与隔离策略按实际系统设计。

> 视频待核对：收发器型号、DE/RE 引脚与有效电平、波特率、终端/偏置配置和课程双板协议。

## 本节目标

- 能区分 UART 协议和 RS485 物理层
- 能正确控制 DE/RE 半双工方向
- 能解释终端、偏置、共地和多节点冲突

## 知识地图

| 名词 | 工程含义 |
|---|---|
| 差分信号 | 用 A/B 电压差表达逻辑 |
| 半双工 | 同一总线同一时刻通常只有一个发送者 |
| DE/RE | 驱动使能/接收使能 |
| 终端电阻 | 长线阻抗匹配 |
| 偏置电阻 | 无发送者时维持确定空闲状态 |
| 主从协议 | 应用层决定谁能发送 |

## 本质理解

RS485 不是另一套串口帧格式，而是把 UART 的单端信号转换成差分总线。它解决距离和抗干扰，不自动解决地址、仲裁、帧边界和校验。


## STM32F103 / HAL 中的实现方式

- STM32 侧仍由 USART 产生字节，外部收发器连接 A/B 总线。
- 发送前切 TX，等待 UART TC 真正发送完最后停止位后再切 RX。
- 多节点需要协议约束同一时刻只有一个发送者；终端/偏置按拓扑和收发器手册设计。

## CubeMX 配置要点

1. 配置 USART 波特率和帧格式。
2. 配置 DE/RE 控制 GPIO 和默认接收状态。
3. 需要不定长协议时配置 IDLE + DMA。
4. 具体引脚、极性、终端和波特率按原理图/视频/手册。

## 常用 HAL API

> STM32 HAL 没有“RS485 协议 API”。RS485 收发器方向由 GPIO 控制，字节传输仍使用 UART HAL；节点地址、帧格式和冲突避免属于项目协议。

### API 速查

| HAL 函数 / 宏 | 作用 | 常见位置 |
|---|---|---|
| `HAL_GPIO_WritePin()` | 控制收发器 DE/RE 方向 | 每次发送前后、初始化 |
| `HAL_UART_Transmit()` | 阻塞发送一帧字节 | 最小主从实验 |
| `HAL_UART_Transmit_DMA()` | DMA 发送较长帧 | 非阻塞发送 |
| `HAL_UART_TxCpltCallback()` | 通知 UART 发送完成 | 用户回调中切回接收态 |
| `HAL_UART_Receive_IT()` | 接收固定长度响应 | 简单短帧 |
| `HAL_UARTEx_ReceiveToIdle_DMA()` | 接收不定长 RS485 帧片段 | 协议接收层 |
| `__HAL_UART_GET_FLAG()` | 读取 TC 等 UART 标志 | 轮询式方向切换 |

### 使用注意

| HAL 函数 / 宏 | 前置条件 | 参数重点 | 返回值 / 阻塞与常见坑 |
|---|---|---|---|
| `HAL_GPIO_WritePin()` | DE/RE 引脚模式和有效电平已按原理图确认 | GPIO 端口、Pin、目标电平 | `void`；非阻塞；把 DE/RE 有效电平写反；发送完成前切回接收 |
| `HAL_UART_Transmit()` | UART 帧格式一致，已切发送态 | buffer、长度、Timeout | 返回 `HAL_StatusTypeDef`；阻塞到完成/超时；未检查返回值；发送前未切方向 |
| `HAL_UART_Transmit_DMA()` | TX DMA 已配置，buffer 有效 | UART 句柄、buffer、长度 | 返回状态；非阻塞；DMA 搬完不等于可随意提前切方向；应以 UART 发送完成事件为准 |
| `HAL_UART_TxCpltCallback()` | IT/DMA 发送链和中断完整 | UART 句柄 | `void`；中断上下文；多串口不判断实例；回调里启动复杂业务 |
| `HAL_UART_Receive_IT()` | 已切接收态，UART NVIC 已开 | buffer、长度 | 返回状态；非阻塞；完成后忘记重启；不定长协议不适合固定长度等待 |
| `HAL_UARTEx_ReceiveToIdle_DMA()` | RX DMA/IDLE 链完整 | buffer、容量 | 返回状态；非阻塞；IDLE 不是完整帧保证；仍需长度/校验/超时状态机 |
| `__HAL_UART_GET_FLAG()` | UART 句柄有效 | 句柄、`UART_FLAG_TC` 等 | 返回标志状态；非阻塞轮询；忙等无超时；混淆 TXE、DMA 完成和 TC |

### 典型调用顺序

```text
接收态初始化 DE/RE
-> 组装完整协议帧
-> HAL_GPIO_WritePin() 切发送态
-> HAL_UART_Transmit() 或 HAL_UART_Transmit_DMA()
-> 确认 UART TC / TxCplt
-> HAL_GPIO_WritePin() 切回接收态
-> Receive IT/DMA 接收并交给协议解析器
```

### 什么时候用哪个函数？

| 场景 | 推荐函数 |
|---|---|
| 最小半双工验证 | GPIO 切方向 + `HAL_UART_Transmit()` + 固定长度接收 |
| 较长帧非阻塞发送 | `HAL_UART_Transmit_DMA()` + 发送完成回调切回接收 |
| 不定长协议接收 | `HAL_UARTEx_ReceiveToIdle_DMA()` + 帧状态机 |
| 轮询确认最后停止位发完 | 带超时检查 `UART_FLAG_TC` |

## 最小实验 / 最小框架

> 代码性质：可直接移植的最小实验框架，变量名需按 CubeMX 实际生成结果调整。

```c
static uint8_t rs485_rx_byte;
static volatile uint8_t rs485_rx_ready;

static void RS485_SetDirection(uint8_t transmit)
{
    HAL_GPIO_WritePin(RS485_DE_GPIO_Port, RS485_DE_Pin,
                      transmit ? RS485_TX_LEVEL : RS485_RX_LEVEL);
}

static uint8_t RS485_WaitTransmissionComplete(uint32_t timeout_ms)
{
    uint32_t start = HAL_GetTick();
    while (__HAL_UART_GET_FLAG(&huart1, UART_FLAG_TC) == RESET)
    {
        if ((uint32_t)(HAL_GetTick() - start) >= timeout_ms) return 0U;
    }
    return 1U;
}

static uint8_t RS485_SendFrame(const uint8_t *data, uint16_t length)
{
    if (!BusScheduler_CanTransmit()) return 0U;

    RS485_SetDirection(1U);
    HAL_StatusTypeDef status = HAL_UART_Transmit(&huart1, data, length,
                                                 RS485_TX_TIMEOUT_MS);
    uint8_t completed = (status == HAL_OK) &&
                        RS485_WaitTransmissionComplete(RS485_TC_TIMEOUT_MS);
    RS485_SetDirection(0U);
    return completed;
}

void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart->Instance == USART1)
    {
        rs485_rx_ready = 1U;
        (void)HAL_UART_Receive_IT(&huart1, &rs485_rx_byte, 1U);
    }
}

RS485_SetDirection(0U);
if (HAL_UART_Receive_IT(&huart1, &rs485_rx_byte, 1U) != HAL_OK)
{
    Error_Handler();
}

while (1)
{
    if (rs485_rx_ready)
    {
        rs485_rx_ready = 0U;
        Protocol_PushByte(rs485_rx_byte);
    }
    if (NodeFrameReadyToSend())
    {
        (void)RS485_SendFrame(Node_GetTxData(), Node_GetTxLength());
    }
}
```

`BusScheduler_CanTransmit()` 表示主从轮询、令牌或静默窗口等冲突避免策略。DE/RE 有效电平、UART 参数、终端和节点协议以收发器手册、原理图和实测为准。

## 调试方法

```text
先验证 TTL UART
-> 确认 DE/RE 电平
-> 确认发送时 A/B 有差分波形
-> 确认发送完成后切回接收
-> 核对两端波特率/协议
-> 长线再检查终端/偏置/拓扑
```

## 常见坑

| 现象 | 常见原因 | 处理方法 |
|---|---|---|
| 只能发不能收 | 发送后未切回 RX | 等待 TC 后切接收 |
| 方向完全反 | DE/RE 有效电平理解错 | 按收发器手册测量 |
| A/B 接反 | 差分极性错误 | 按设备定义核对 |
| 长线不稳 | 终端/偏置/星形拓扑 | 按总线规范整改 |
| 多节点冲突 | 同时发送 | 设计主从/令牌/仲裁协议 |
| 偶发乱码 | 共地/屏蔽/波特率问题 | 检查参考地和波形 |
