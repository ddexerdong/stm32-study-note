# RS485 物理层

> 能力定位：在 UART 字节流外增加差分、半双工和方向控制能力。
>
> 原始来源：[[15_RS485与CAN]]。

## 组成

STM32 仍使用 UART/USART；外部 RS485 收发器把单端逻辑信号转换为 A/B 差分信号。RS485 主要定义物理层，不自动提供地址、命令和校验协议。

## 半双工方向

```text
默认接收
-> DE/RE 切发送
-> UART 发送
-> 等待真正发送完成
-> DE/RE 切回接收
```

## 总线要点

- A/B 极性和命名可能因模块而异，应看原理图或波形。
- 长线和高速通信需要合理的终端电阻、偏置和总线拓扑。
- 多节点需要统一波特率和应用协议。
- 共地与隔离策略按实际系统设计。

> 视频待核对：收发器型号、DE/RE 引脚与有效电平、波特率、终端/偏置配置和课程双板协议。

## 知识地图

| 名词 | 工程含义 |
|---|---|
| 差分信号 | 用 A/B 电压差表达逻辑 |
| 半双工 | 同一总线同一时刻通常只有一个发送者 |
| DE/RE | 驱动使能/接收使能 |
| 终端电阻 | 长线阻抗匹配 |
| 偏置电阻 | 无发送者时维持确定空闲状态 |
| 主从协议 | 应用层决定谁能发送 |

## 本质理解

RS485 不是另一套串口帧格式，而是把 UART 的单端信号转换成差分总线。它解决距离和抗干扰，不自动解决地址、仲裁、帧边界和校验。

为什么这样做：先建立硬件和数据流模型，再记 HAL API，才能在 API 变化或板卡变化时仍然定位问题。

## STM32F103 / HAL 中的实现方式

- STM32 侧仍由 USART 产生字节，外部收发器连接 A/B 总线。
- 发送前切 TX，等待 UART TC 真正发送完最后停止位后再切 RX。
- 多节点需要协议约束同一时刻只有一个发送者；终端/偏置按拓扑和收发器手册设计。

## CubeMX 配置要点

1. 配置 USART 波特率和帧格式。
2. 配置 DE/RE 控制 GPIO 和默认接收状态。
3. 需要不定长协议时配置 IDLE + DMA。
4. 具体引脚、极性、终端和波特率按原理图/视频/手册。

## 常用 HAL API

| API / 对象 | 作用 | 常见位置 |
|---|---|---|
| `HAL_UART_Transmit` | 发送 RS485 字节 | 方向切换之间 |
| `HAL_UART_Receive_IT/DMA` | 接收响应 | 接收状态 |
| `__HAL_UART_GET_FLAG` | 检查 TC 等状态 | 发送完成确认 |
| `HAL_GPIO_WritePin` | 控制 DE/RE | 半双工方向 |

## 最小实验 / 最小框架

> 代码性质：可直接移植的最小实验框架，变量名需按 CubeMX 实际生成结果调整。

```c
RS485_SetTx();
HAL_UART_Transmit(&huart1, data, len, timeout);
while (__HAL_UART_GET_FLAG(&huart1, UART_FLAG_TC) == RESET) {}
RS485_SetRx();
```

## 调试方法

```text
先验证 TTL UART
-> 确认 DE/RE 电平
-> 确认发送时 A/B 有差分波形
-> 确认发送完成后切回接收
-> 核对两端波特率/协议
-> 长线再检查终端/偏置/拓扑
```

## 常见坑

| 现象 | 常见原因 | 处理方法 |
|---|---|---|
| 只能发不能收 | 发送后未切回 RX | 等待 TC 后切接收 |
| 方向完全反 | DE/RE 有效电平理解错 | 按收发器手册测量 |
| A/B 接反 | 差分极性错误 | 按设备定义核对 |
| 长线不稳 | 终端/偏置/星形拓扑 | 按总线规范整改 |
| 多节点冲突 | 同时发送 | 设计主从/令牌/仲裁协议 |
| 偶发乱码 | 共地/屏蔽/波特率问题 | 检查参考地和波形 |
