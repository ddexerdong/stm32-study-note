# 串口协议解析

> 项目目标：把 UART 字节流稳定地还原成完整、可验证的业务帧。
>
> 原始来源：[[04_串口与DMA]]。

## 分层

```text
UART/RS485 接收
-> DMA/中断缓冲区
-> 帧边界检测
-> 帧头和长度校验
-> 校验和/CRC
-> 命令与字段解析
-> 业务分发
```

## 必须处理的问题

- 粘包：一次收到多帧。
- 半包：一帧分多次收到。
- 噪声：帧头前存在无效字节。
- 超时：帧长时间不完整。
- 缓冲区溢出：生产速度高于消费速度。

## 状态机思路

按“找帧头 -> 读固定头 -> 得到长度 -> 等完整帧 -> 校验 -> 分发”处理。IDLE 只能提示总线暂时空闲，不能替代协议长度和校验。

> 视频待核对：课程雷达模块的型号、波特率、帧头、长度、字段和校验方式。

## 本节目标

- 能设计带长度、命令、载荷和校验的帧格式。
- 能用状态机处理半包、粘包、超时和错误恢复。
- 能把 IDLE + DMA 接收与业务命令分发解耦。

## 知识地图

| 问题 | 工程含义 |
|---|---|
| 半包 | 一帧分多次到达 |
| 粘包 | 多帧一次到达 |
| 帧头 | 从噪声中定位候选帧 |
| 长度 | 判断完整帧边界 |
| 命令字 | 决定 payload 解释方式 |
| 校验 | 拒绝传输错误或错位 |
| 超时 | 放弃长期不完整帧 |

## 本质理解

UART/DMA 回调只告诉你“收到一些字节”，不会保证正好一帧。协议解析器必须是持续消费字节流的状态机，能跨回调保留状态，也能在错误后重新找帧头。

## 推荐帧格式

```text
SOF | Version | Command | Length | Payload | Checksum/CRC
```

长度和校验算法必须由协议明确，不能由接收次数推断。

## CubeMX 与接收链

1. USART 配置波特率/8N1。
2. RX DMA 设合适模式和缓冲长度。
3. 使用 IDLE/RxEvent 把新字节送入 ring buffer。
4. 解析器在主循环持续取字节。

## 本项目使用的 HAL 层

### API 速查

| 接收链动作 | HAL 函数 |
|---|---|
| 最小阻塞验证 | `HAL_UART_Receive()` |
| 固定长度小帧 | `HAL_UART_Receive_IT()` |
| 不定长数据入口 | `HAL_UARTEx_ReceiveToIdle_DMA()` |
| 获取本次有效长度 | `HAL_UARTEx_RxEventCallback()` |
| 固定长度完成通知 | `HAL_UART_RxCpltCallback()` |
| 接收错误恢复 | `HAL_UART_ErrorCallback()` / `HAL_UART_DMAStop()` |

### 使用注意

| HAL 函数 | 前置条件与调用位置 | 返回值 / 阻塞 | 常见坑 |
|---|---|---|---|
| `HAL_UART_Receive()` | 串口参数和接线确认阶段 | 阻塞到收满/超时 | 用它直接实现长期不定长协议 |
| `HAL_UART_Receive_IT()` | UART NVIC 已开，使用静态 buffer | 非阻塞，返回状态 | 完成回调后忘记重启；半包永远等不满 |
| `HAL_UARTEx_ReceiveToIdle_DMA()` | RX DMA/IDLE 完整配置 | 非阻塞，返回状态 | 把一次 RxEvent 当完整协议帧 |
| `HAL_UARTEx_RxEventCallback()` | Receive-to-Idle 已启动 | 中断上下文 | 用 `strlen` 代替 Size；回调中直接解析大帧 |
| `HAL_UART_RxCpltCallback()` | 使用固定长度 IT/DMA | 中断上下文 | 与 RxEvent 回调混淆 |
| `HAL_UART_ErrorCallback()` / `HAL_UART_DMAStop()` | 记录错误并重建接收状态 | 回调非阻塞；DMAStop 返回状态 | 只重启 HAL，不清协议解析器的半帧状态 |

### 典型调用顺序

```text
MX_DMA_Init()
-> MX_USARTx_UART_Init()
-> 定义长期有效 DMA buffer 和 ring buffer
-> HAL_UARTEx_ReceiveToIdle_DMA()
-> RxEventCallback 按 Size 复制新字节
-> 主循环状态机按帧头/长度/校验消费 ring buffer
-> 错误或超时后复位解析状态并重启接收链
```

### 什么时候用哪个函数？

| 场景 | 推荐函数 |
|---|---|
| 串口线和参数最小验证 | `HAL_UART_Receive()` |
| 单字节/固定短命令 | `HAL_UART_Receive_IT()` |
| 不定长命令、雷达帧、连续字节流 | `HAL_UARTEx_ReceiveToIdle_DMA()` + ring buffer |
| 协议分帧 | 不靠 HAL 回调次数，使用长度/校验/超时状态机 |

## 状态机框架

> 代码性质：伪代码，用于说明业务逻辑，不是可直接编译代码。

```c
typedef struct
{
    uint8_t version;
    uint8_t command;
    uint16_t length;
    uint8_t payload[PROTOCOL_MAX_PAYLOAD];
    uint8_t checksum;
} ProtocolFrame_t;

typedef enum
{
    PARSER_FIND_SOF = 0,
    PARSER_READ_HEADER,
    PARSER_READ_PAYLOAD,
    PARSER_READ_CHECKSUM
} ParserState_t;

static uint8_t Protocol_Checksum(const uint8_t *data, uint16_t length)
{
    uint8_t checksum = 0U;
    for (uint16_t i = 0U; i < length; ++i) checksum ^= data[i];
    return checksum;
}

static void Protocol_Dispatch(const ProtocolFrame_t *frame)
{
    switch (frame->command)
    {
    case CMD_LED_SET:
        App_RequestLed(frame->payload, frame->length);
        break;
    case CMD_BUZZER_SET:
        App_RequestBuzzer(frame->payload, frame->length);
        break;
    case CMD_SERVO_SET:
        App_RequestServo(frame->payload, frame->length);
        break;
    default:
        Protocol_ReportUnsupported(frame->command);
        break;
    }
}

static void Parser_PushByte(ProtocolParser_t *parser, uint8_t byte)
{
    switch (parser->state)
    {
    case PARSER_FIND_SOF:
        Parser_TryStartFrame(parser, byte);
        break;
    case PARSER_READ_HEADER:
        Parser_PushHeaderByte(parser, byte);
        break;
    case PARSER_READ_PAYLOAD:
        Parser_PushPayloadByte(parser, byte);
        break;
    case PARSER_READ_CHECKSUM:
        if (Protocol_Checksum(parser->raw, parser->raw_length) == byte)
            Protocol_Dispatch(&parser->frame);
        Parser_Reset(parser);
        break;
    }
}

void Protocol_PushBytes(const uint8_t *data, uint16_t length)
{
    for (uint16_t i = 0U; i < length; ++i)
    {
        Parser_PushByte(&parser, data[i]);
    }
    Parser_CheckTimeout(&parser, HAL_GetTick());
}
```

解析器跨多次 DMA/IDLE 回调保留状态，因此能处理半包；循环持续消费全部字节，因此能处理粘包。SOF、长度字段、checksum/CRC 和命令格式必须由项目协议明确。

## 命令分发

LED、蜂鸣器、舵机命令先验证长度和参数范围，再设置业务请求；不要在 UART 回调里直接执行长动作。

## 调试顺序

```text
保存原始 HEX
-> 单帧
-> 分片输入
-> 多帧粘连
-> 错误校验
-> 噪声前缀
-> 超时恢复
-> 长时间压力测试
```

## 常见坑

| 坑 | 后果 | 修复 |
|---|---|---|
| 一次 IDLE=一帧 | 半包时误解析 | 按长度和状态机 |
| `strlen` 处理二进制 | 遇 0 截断 | 始终显式长度 |
| 无边界检查 | 缓冲区溢出 | 检查最大 payload |
| 校验前执行业务 | 错帧触发动作 | 验证后分发 |
| 错误后不复位 | 后续全乱 | 重新搜索帧头 |
