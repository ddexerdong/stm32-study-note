# 传感器采集与显示

> 项目目标：把不同传感器统一到“通信、原始数据、换算、显示”分层流程。

## 通用 bring-up

```text
确认供电/共地/总线
-> 地址或片选检测
-> 读设备 ID
-> 写最少配置
-> 连续读取原始数据
-> 打印原始字节/数值
-> 按资料换算
-> OLED/串口显示
-> 加入超时与异常状态
```

## 分层接口

| 层 | 建议输出 |
|---|---|
| Bus | HAL 状态和原始字节 |
| Driver | 芯片原始结构体 |
| Convert | 带单位的工程值 |
| App | 显示、告警、记录和联网 |

## 组合示例

- [[DHT11单总线温湿度]] + [[OLED显示模块]]。
- [[MPU6050姿态传感器]] + [[USART与串口协议]]。
- [[BMP280_SPL06气压计]] + OLED/串口显示。
- MAX30102/VL53L0X 先完成原始数据，再接算法或库。

所有地址、寄存器、换算公式和库接口必须来自视频或模块资料。

## 本节目标

- 能统一组织 ADC、I2C、SPI 传感器的数据链。
- 能把原始值、换算值、有效状态和时间戳组织成快照。
- 能先验证数据可信度，再接 OLED 或串口显示。

## 知识地图

| 层 | 输出 | 可信度问题 |
|---|---|---|
| Bus | 原始字节/HAL 状态 | 接线、地址、时序 |
| Driver | 原始结构体 | 字节序、符号、长度 |
| Convert | 工程单位 | 量程、校准、公式 |
| Filter | 平滑值/有效标志 | 延迟、异常值 |
| Display | 文本/图形 | 格式和刷新节奏 |

## 本质理解

项目价值在于建立可验证的数据链，而不是让 OLED 出现一个数字。任何显示值都应能回溯到原始字节、配置、换算和有效性判断。

## 系统组成

- ADC 传感器：AO -> ADC -> 电压 -> 标定模型。
- I2C 传感器：地址/ID -> 配置 -> 连续寄存器 -> 换算。
- SPI 传感器：CS/模式 -> ID -> 配置 -> 原始数据。
- 显示：串口先验证，OLED 后集成。

## 数据流

```text
采样节拍
-> 读取 ID/状态/原始值
-> 合法性检查
-> 换算
-> 滑动平均/限幅
-> 数据快照
-> 串口/OLED/网络
```

## CubeMX 配置

1. 配置 ADC/I2C/SPI 和必要 DMA/TIM。
2. 配置日志 USART。
3. 配置 OLED I2C，确认总线地址不冲突。
4. 每个外设先独立跑通，再合并。

## 本项目使用的 HAL 层

### API 速查

| 数据链动作 | HAL 函数 |
|---|---|
| ADC 单次验证 | `HAL_ADC_Start()` + `HAL_ADC_PollForConversion()` + `HAL_ADC_GetValue()` |
| ADC 连续采样 | `HAL_ADC_Start_DMA()` |
| I2C 传感器寄存器访问 | `HAL_I2C_Mem_Read()`、`HAL_I2C_Mem_Write()` |
| SPI 传感器访问 | `HAL_SPI_TransmitReceive()` + GPIO CS |
| OLED 数据发送 | `HAL_I2C_Master_Transmit()` |
| 串口输出 raw/错误码 | `HAL_UART_Transmit()` 或 `printf` |

### 使用注意

| HAL 函数 | 前置条件与调用位置 | 返回值 / 阻塞 | 常见坑 |
|---|---|---|---|
| `HAL_ADC_Start()` + `HAL_ADC_PollForConversion()` + `HAL_ADC_GetValue()` | ADC 校准后，在最小测试中调用 | Poll 阻塞；其余检查返回状态 | 直接接滤波/显示，未先记录 raw |
| `HAL_ADC_Start_DMA()` | DMA/Rank/buffer 已配置 | 非阻塞 | Rank 与数组下标错；buffer 生命周期不足 |
| `HAL_I2C_Mem_Read()`、`HAL_I2C_Mem_Write()` | 地址和寄存器宽度已核对，在 BSP 内调用 | 阻塞并返回状态 | 地址左移、字节序或长度错误 |
| `HAL_SPI_TransmitReceive()` + GPIO CS | SPI 模式/CS 已确认，在 BSP 内封装事务 | 阻塞并返回状态 | CPOL/CPHA、dummy、CS 边界错误 |
| `HAL_I2C_Master_Transmit()` | OLED 控制器协议已确认 | 阻塞并返回状态 | 显示异常被误判成传感器采样错误 |
| `HAL_UART_Transmit()` 或 `printf` | 调试串口可用 | 阻塞 | 高频打印改变采样节奏 |

### 典型调用顺序

```text
初始化日志串口
-> 分别初始化 ADC/I2C/SPI/OLED
-> 每个传感器先读 ID/raw 并检查 HAL_OK
-> 形成带 valid/time/error 的数据快照
-> 主循环按独立节拍完成换算、滤波和显示
```

### 什么时候用哪个函数？

| 场景 | 推荐函数 |
|---|---|
| 单通道 ADC bring-up | ADC 轮询三件套 |
| 多通道固定节拍采样 | TIM TRGO + `HAL_ADC_Start_DMA()` |
| I2C 寄存器型传感器 | `HAL_I2C_Mem_Read()`、`HAL_I2C_Mem_Write()` |
| SPI 命令型传感器 | 手动 CS + `HAL_SPI_Transmit()`、`HAL_SPI_TransmitReceive()` |
| 最先验证数据可信度 | UART 输出 raw、状态和时间戳，再接 OLED |

## 核心接口框架

> 代码性质：示例框架，用于理解流程，不能保证直接编译。

```c
typedef struct {
    uint8_t valid;
    float temperature;
    float humidity;
    float pressure;
} SensorSnapshot_t;

void Sensors_Task(void)
{
    SensorRaw_t raw;
    if (Sensors_ReadRaw(&raw) && Sensors_Convert(&raw, &snapshot))
        snapshot.valid = 1;
}
```

## 调试顺序

```text
单总线/单通道
-> ID 或 raw
-> 换算中间量
-> 滤波前后对比
-> 串口输出
-> OLED 显示
-> 多传感器并发
```

## 常见坑

| 坑 | 处理 |
|---|---|
| 显示正常但数据假 | 保留 raw 和 valid |
| 多设备总线冲突 | 检查地址、CS 和上拉 |
| 刷新阻塞采样 | 分离采样节拍和显示节拍 |
| 单位混乱 | 结构体字段带明确单位 |
| 失败沿用旧值 | 增加时间戳和有效标志 |

## 可扩展方向
