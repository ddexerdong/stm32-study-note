## 本质理解

电机章节解决的不是“让 GPIO 输出高低电平”这么简单，而是把 STM32 的小电流控制信号转换成电机需要的功率输出。

STM32 只负责三件事：

```text
方向：AIN1 / AIN2
速度：PWMA 的 PWM 占空比
使能：STBY
```

真正给电机供电的是驱动芯片和电机电源。STM32 直接接电机，轻则电机不转，重则 GPIO 或芯片损坏。

PDF 中高级定时器章节提到 PWM、互补输出、死区和刹车面向电机/功率控制场景；本课程的 TB6612FNG 入门实验先按普通单路 PWM 调速理解，不把高级电机控制展开。

## 工作流程 / 原理

### 电机控制链路

```text
STM32 GPIO 输出方向
-> TB6612FNG AIN1/AIN2
-> H 桥决定电机两端极性
-> 电机正转 / 反转 / 刹车 / 停止

STM32 TIM 输出 PWM
-> TB6612FNG PWMA
-> 平均电压/电流变化
-> 电机速度变化
```

### TB6612FNG A 路逻辑框架

具体真值表和引脚以模块资料、视频和实际开发板原理图为准。笔记只先建立工程理解：

| STBY | PWMA | AIN1 | AIN2 | 工程含义 |
|------|------|------|------|----------|
| 低 | 任意 | 任意 | 任意 | 待机，不驱动 |
| 高 | PWM | 高 | 低 | 一个方向转动 |
| 高 | PWM | 低 | 高 | 反方向转动 |
| 高 | 0 | 任意 | 任意 | 不输出有效调速脉冲 |
| 高 | PWM | 同电平 | 同电平 | 可能为刹车或停止，需查模块资料 |

> 视频待核对：TB6612FNG 的 AIN1/AIN2/PWMA/STBY 接线、电机供电电压、PWM 通道、方向逻辑和停止/刹车真值表。

以实际开发板原理图和 CubeMX 配置为准。

### 工程模板思路

课程 `[27]` 的重点是把“能跑的实验”整理成“能长期维护的工程”。

建议结构：

```text
Core/
├── Inc/
│   └── main.h
├── Src/
│   └── main.c
BSP/
├── motor_tb6612.c
└── motor_tb6612.h
README.md
```

`main.c` 负责调用初始化和业务流程；`BSP/motor_tb6612.c` 负责电机控制细节。这样以后换引脚、换定时器、改驱动模块时，不需要到处找散落代码。

8. 用户代码写在 `USER CODE` 区域；BSP 文件放在工程目录后，需要在 MDK 中加入到工程分组。

### 工程模板整理

1. 保留 CubeMX 生成的 `Core/`、`Drivers/` 等目录。
2. 新建 `BSP/` 目录存放板级驱动。

## 最小代码

以下代码只作为最小示例框架。引脚名、定时器句柄、通道号必须按 CubeMX 实际生成结果修改。

以实际开发板原理图和 CubeMX 配置为准。

### `BSP/motor_tb6612.h`

```c
#ifndef MOTOR_TB6612_H
#define MOTOR_TB6612_H

#include "main.h"

void Motor_Init(void);
void Motor_SetSpeed(int16_t speed);
void Motor_Stop(void);

#endif
```

### `BSP/motor_tb6612.c`

```c
#include "motor_tb6612.h"
#include "tim.h"

#define MOTOR_PWM_TIM      htim3
#define MOTOR_PWM_CHANNEL  TIM_CHANNEL_1

#define MOTOR_AIN1_PORT    GPIOB
#define MOTOR_AIN1_PIN     GPIO_PIN_0
#define MOTOR_AIN2_PORT    GPIOB
#define MOTOR_AIN2_PIN     GPIO_PIN_1
#define MOTOR_STBY_PORT    GPIOB
#define MOTOR_STBY_PIN     GPIO_PIN_2

#define MOTOR_PWM_MAX      999

void Motor_Init(void)
{
    HAL_GPIO_WritePin(MOTOR_STBY_PORT, MOTOR_STBY_PIN, GPIO_PIN_SET);
    HAL_TIM_PWM_Start(&MOTOR_PWM_TIM, MOTOR_PWM_CHANNEL);
    Motor_Stop();
}

void Motor_SetSpeed(int16_t speed)
{
    uint16_t duty = 0;

    if (speed > MOTOR_PWM_MAX)
    {
        speed = MOTOR_PWM_MAX;
    }
    else if (speed < -MOTOR_PWM_MAX)
    {
        speed = -MOTOR_PWM_MAX;
    }

    if (speed > 0)
    {
        HAL_GPIO_WritePin(MOTOR_AIN1_PORT, MOTOR_AIN1_PIN, GPIO_PIN_SET);
        HAL_GPIO_WritePin(MOTOR_AIN2_PORT, MOTOR_AIN2_PIN, GPIO_PIN_RESET);
        duty = (uint16_t)speed;
    }
    else if (speed < 0)
    {
        HAL_GPIO_WritePin(MOTOR_AIN1_PORT, MOTOR_AIN1_PIN, GPIO_PIN_RESET);
        HAL_GPIO_WritePin(MOTOR_AIN2_PORT, MOTOR_AIN2_PIN, GPIO_PIN_SET);
        duty = (uint16_t)(-speed);
    }
    else
    {
        Motor_Stop();
        return;
    }

    __HAL_TIM_SET_COMPARE(&MOTOR_PWM_TIM, MOTOR_PWM_CHANNEL, duty);
}

void Motor_Stop(void)
{
    HAL_GPIO_WritePin(MOTOR_AIN1_PORT, MOTOR_AIN1_PIN, GPIO_PIN_RESET);
    HAL_GPIO_WritePin(MOTOR_AIN2_PORT, MOTOR_AIN2_PIN, GPIO_PIN_RESET);
    __HAL_TIM_SET_COMPARE(&MOTOR_PWM_TIM, MOTOR_PWM_CHANNEL, 0);
}
```

### `Core/Src/main.c`

在 `USER CODE BEGIN Includes` 中包含头文件：

```c
#include "motor_tb6612.h"
```

在 `USER CODE BEGIN 2` 中启动电机模块：

```c
Motor_Init();
```

在 `while (1)` 的 `USER CODE` 区域中做最小动作验证：


## 调试方法

按“硬件 -> CubeMX -> 启动函数 -> PWM -> 业务逻辑”的顺序排查。

### 硬件层

1. 电机电源是否接到驱动模块 VM。
2. STM32、驱动模块、电机电源是否共地。
3. VCC 逻辑电源是否符合模块要求。
4. STBY 是否被拉高或由 GPIO 输出高电平。
5. 电机是否接到正确输出端。

### CubeMX 层

1. AIN1/AIN2/STBY 是否配置为输出。
2. PWMA 对应引脚是否真的是所选 TIM 通道。
3. PWM 的 PSC/ARR 是否合理。
4. 生成工程后 `MX_GPIO_Init()` 和 `MX_TIMx_Init()` 是否被调用。

### 启动函数层

1. 是否调用 `HAL_TIM_PWM_Start()`。
2. 是否先使能 STBY。
3. 是否调用 `Motor_Init()`。
4. `__HAL_TIM_SET_COMPARE()` 的值是否在 `0~ARR` 范围内。

### 常见坑

| 现象 | 常见原因 | 处理 |
|------|----------|------|
| 电机完全不转 | STBY 未使能、VM 未供电、未共地 | 查 STBY、VM、GND |
| 电机只嗡嗡响 | 占空比太小、电源带不动、机械卡住 | 提高占空比，检查电源和负载 |
| 方向反了 | AIN1/AIN2 逻辑或电机线方向相反 | 调换方向逻辑或电机线 |
| PWM 无效 | 忘记 `HAL_TIM_PWM_Start()` | 初始化后启动 PWM |
| 程序重新生成后代码丢失 | 写在 `USER CODE` 区域外 | 业务代码放 USER CODE，BSP 独立文件加入工程 |
| 电机一转单片机复位 | 电机电源干扰或供电不足 | 电机单独供电、共地、加滤波 |

## 工程意义

电机控制是从“点灯型 GPIO 实验”进入“真实负载控制”的分界线。它会逼着我考虑：

- GPIO 只能发控制信号，不能直接带大电流负载。
- PWM 不只是让 LED 变亮，也可以控制平均功率。
- 工程代码不能都写在 `main.c`，否则后面模块一多就很难维护。

---

## 易混淆点

| 容易混淆 | 正确理解 |
|----------|----------|
| STM32 直接驱动电机 | STM32 只输出逻辑控制，电机由驱动芯片和电机电源供电 |
| VCC 和 VM | VCC 是逻辑电源，VM 是电机电源 |
| PWMA 和 AIN1/AIN2 | PWMA 控速度，AIN1/AIN2 控方向 |
| PWM 频率和占空比 | 频率由 PSC/ARR 决定，占空比由 CCR 决定 |
| 停止和刹车 | 具体逻辑取决于驱动芯片真值表，不能凭感觉写死 |
| BSP 文件和 CubeMX 文件 | BSP 是自己维护的板级代码，CubeMX 文件可重新生成 |

---

## 我的理解

我现在把 TB6612FNG 理解成一个“电机电流开关盒”。STM32 不碰大电流，只告诉这个盒子：往哪个方向转、转多快、要不要待机。

以后遇到电机不转，我会先按这个顺序查：

```text
电机电源 VM
-> 共地
-> STBY
-> AIN1/AIN2 方向
-> PWM 是否启动
-> CCR 是否大于 0
-> 电机和驱动是否发热或保护
```

工程模板这部分，我的理解是：`main.c` 应该越来越像流程表，而不是所有细节的垃圾桶。电机、传感器、显示屏都应该逐渐拆到独立 BSP 文件里。

## [26] TB6612FNG驱动有刷电机

> 视频待核对：TB6612FNG 的 AIN1/AIN2/PWMA/STBY 接线、VM/VCC、电机供电、PWM 通道、方向/停止/刹车真值表。

### 实验目标

用 STM32 输出方向 GPIO 和 PWM，占空比控制有刷电机转速，通过 TB6612FNG 承担电机电流。

### 保守控制关系

| 信号 | 工程含义 | 注意 |
|------|----------|------|
| `AIN1/AIN2` | 控制方向或停止状态 | 具体组合必须核对真值表 |
| `PWMA` | PWM 调速输入 | PWM 通道以 CubeMX 为准 |
| `STBY` | 待机/使能控制 | 未使能时电机不会转 |
| `VM` | 电机电源 | 不等于 STM32 3.3 V |
| `VCC` | 逻辑电源 | 电平兼容按模块资料确认 |

### CubeMX 配置要点

1. 方向控制脚配置为 GPIO 输出。
2. `STBY` 配置为 GPIO 输出，或按模块接线固定使能。
3. PWM 对应 TIM 通道配置为 PWM Generation。
4. 启动 PWM 后再改变 CCR 控制速度。
5. 所有接线和 PWM 通道以实际开发板原理图和 CubeMX 配置为准。

### 最小代码

常见位置：`BSP/motor_tb6612.c`

```c
void Motor_SetSpeedPercent(int16_t percent)
{
    if (percent > 100)
    {
        percent = 100;
    }
    else if (percent < -100)
    {
        percent = -100;
    }

    /* 视频待核对：方向 GPIO 的真值表。 */
    if (percent >= 0)
    {
        HAL_GPIO_WritePin(MOTOR_IN1_GPIO_Port, MOTOR_IN1_Pin, GPIO_PIN_SET);
        HAL_GPIO_WritePin(MOTOR_IN2_GPIO_Port, MOTOR_IN2_Pin, GPIO_PIN_RESET);
        __HAL_TIM_SET_COMPARE(&htimx, TIM_CHANNEL_x, percent);
    }
    else
    {
        HAL_GPIO_WritePin(MOTOR_IN1_GPIO_Port, MOTOR_IN1_Pin, GPIO_PIN_RESET);
        HAL_GPIO_WritePin(MOTOR_IN2_GPIO_Port, MOTOR_IN2_Pin, GPIO_PIN_SET);
        __HAL_TIM_SET_COMPARE(&htimx, TIM_CHANNEL_x, -percent);
    }
}
```

### 调试方法

- 先不接电机，只看 PWM 引脚是否有波形。
- 再确认 `STBY` 是否处于使能状态。
- 电机不转先查 VM 电源和共地，不要只改代码。
- 电机发热或驱动发热时立即断电检查。

### 常见坑

- STM32 直接接电机。
- VM/VCC 混淆。
- `HAL_TIM_PWM_Start()` 没调用。
- 方向真值表没核对就写死。

## [27] 手动建立工程模板与CubeMX后续用法（重要）

### 实验目标

把外设业务从 `main.c` 逐步拆到 BSP 文件中，同时理解 CubeMX 重新生成代码时哪些区域会保留。

### 推荐分工

| 位置 | 放什么 |
|------|--------|
| `Core/Src/main.c` | 初始化顺序、主循环流程、任务调度 |
| `Core/Src/*.c` | CubeMX 生成的外设初始化 |
| `BSP/xxx.c` | 自己写的模块驱动实现 |
| `BSP/xxx.h` | 模块对外 API、宏和结构体声明 |
| MDK Groups | 按 Core、Drivers、BSP 分组管理文件 |

课程最终模板目录需要视频核对，不要编造固定目录。

### CubeMX 后续维护策略

1. CubeMX 管外设初始化，不把业务逻辑写进自动生成区域外的危险位置。
2. 自己写的 BSP 文件手动加入 MDK Group。
3. 头文件路径加入 Include Path。
4. 每次重新生成后，检查 `USER CODE` 区域和手动添加文件是否仍在工程中。
5. 重要配置变更先提交或备份，再重新生成。

### 最小 BSP 结构

常见位置：`BSP/example.h`

```c
#ifndef EXAMPLE_H
#define EXAMPLE_H

#include "main.h"

void Example_Init(void);
void Example_Task(void);

#endif
```

常见位置：`BSP/example.c`

```c
#include "example.h"

void Example_Init(void)
{
}

void Example_Task(void)
{
}
```

### 常见坑

- 把所有业务都堆在 `main.c`。
- 新增 `.c` 文件后忘记加入 MDK 工程。
- 新增 `.h` 文件后忘记 Include Path。
- 代码写在非 USER CODE 区域，被 CubeMX 覆盖。
