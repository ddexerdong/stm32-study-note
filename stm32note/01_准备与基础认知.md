## 本质理解

### ARM 内核和 STM32 的关系

ARM 公司设计的是 **Cortex-M3 内核**，包括 CPU 执行单元、指令集、NVIC 中断控制器、SysTick 等核心模块。

ST 公司购买 ARM 授权，在 Cortex-M3 外围加入 Flash、SRAM、GPIO、USART、ADC、TIM、DMA 等片上外设，封装成 STM32F103C8T6。

```text
Cortex-M3 内核（ARM 设计）
├── CPU 核心：取指、译码、执行
├── NVIC：嵌套向量中断控制器
└── SysTick：24 位系统定时器

STM32F103C8T6（ST 设计）
= Cortex-M3 内核
+ 64 KB Flash
+ 20 KB SRAM
+ GPIOA/B/C
+ USART1/2/3
+ SPI1/2、I2C1/2
+ TIM1/2/3/4
+ ADC1/2
+ DMA
```

### 寄存器是什么

寄存器就是芯片内部一组**有特殊功能的固定地址存储单元**。CPU 往这些地址写不同的值，硬件行为就会变化。

> 代码性质：可直接移植的最小实验框架，变量名需按 CubeMX 实际生成结果调整。

```c
// GPIOB 的 ODR（Output Data Register，输出数据寄存器）
// 地址示例：0x40010C0C
*(volatile uint32_t *)0x40010C0C = 0x0001;  // PB0 输出高电平，其余位为低
*(volatile uint32_t *)0x40010C0C = 0x0000;  // GPIOB 全部输出低电平
```

`volatile` 的作用：告诉编译器这个地址可能被硬件或中断改变，每次都要真实读写，不能随便优化。

### HAL 库的定位

直接操作寄存器有三个问题：

1. 地址和位定义难记。
2. 位操作容易写错。
3. 代码和具体芯片强绑定，可移植性差。

HAL（Hardware Abstraction Layer）把寄存器操作封装成函数，让应用代码更接近“我要控制哪个外设”。

> 代码性质：可直接移植的最小实验框架，变量名需按 CubeMX 实际生成结果调整。

```c
// 裸寄存器写法：需要知道地址和具体位含义
*(volatile uint32_t *)0x40010C0C |= (1 << 0);

// HAL 写法：表达的是工程意图
HAL_GPIO_WritePin(GPIOB, GPIO_PIN_0, GPIO_PIN_SET);
```

HAL 函数命名通常是：

```text
HAL_外设_操作()
```

例如：

| 函数 | 含义 |
|------|------|
| `HAL_GPIO_WritePin()` | 写 GPIO 输出电平 |
| `HAL_GPIO_ReadPin()` | 读 GPIO 输入电平 |
| `HAL_UART_Transmit()` | 串口发送 |
| `HAL_ADC_Start()` | 启动 ADC |
| `HAL_TIM_Base_Start_IT()` | 启动定时器中断 |

## 工作流程 / 原理

### 核心板、面包板、扩展板

#### 核心板

核心板 = STM32 芯片 + 晶振 + 复位电路 + LDO 稳压 + 排针引出的 GPIO。

STM32F103C8T6 核心板常用引脚：

| 引脚 | 功能 | 注意事项 |
|------|------|----------|
| 3V3 | 3.3 V 电源 | 给 STM32 和 3.3 V 外设供电 |
| 5V | 5 V 输入 / 输出 | USB 供电时常输出 5 V，也可外部输入 5 V |
| GND | 地 | **所有外设必须和 STM32 共地** |
| PA9 / PA10 | USART1 TX / RX | 串口通信或 USB-TTL 调试 |
| SWDIO / SWCLK | SWD 调试接口 | 连接 ST-Link / DAP-Link 烧录调试 |
| BOOT0 | 启动模式选择 | 正常运行时通过 10 kΩ 下拉到 GND，从 Flash 启动 |
| NRST | 复位 | 低电平复位，通常已有上拉 |
| PC13 | 板载 LED | 多数核心板为低电平点亮，实际以板子原理图为准 |

#### 面包板

面包板用于免焊接搭电路。中间沟槽两侧不互通，同一侧每列 5 个孔通常纵向连通，电源轨通常横向连通。

```text
俯视图：

┌────────────────────────────────────┐
│ + ───────────────────────────── + │  横向连通：电源轨
│ - ───────────────────────────── - │  横向连通：地轨
├────────────────────────────────────┤
│ │ │ │ │ │ │ │ │ │  ...  │ │ │ │ │ │  纵向 5 孔连通
├────────────────────────────────────┤  中间沟槽，两侧不互通
│ │ │ │ │ │ │ │ │ │  ...  │ │ │ │ │ │  纵向 5 孔连通
├────────────────────────────────────┤
│ + ───────────────────────────── + │
│ - ───────────────────────────── - │
└────────────────────────────────────┘
```

关键约束：

- 中间横向沟槽两侧的孔不互通，DIP 芯片要跨沟槽插。
- 每列纵向 5 个孔通常相通，但上下半区不互通。
- 老旧面包板和便宜杜邦线容易接触不良，异常时先用万用表蜂鸣档确认连通性。

### STM32 命名规则

```text
STM32 F 103 C 8 T 6
 │    │  │  │ │ │ └─ 温度范围：6 = 工业级（-40~85 ℃）
 │    │  │  │ │ └─── 封装：T = LQFP
 │    │  │  │ └───── Flash 容量：8 = 64 KB，B = 128 KB
 │    │  │  └─────── 引脚数：C = 48 pin，R = 64 pin
 │    │  └────────── 子系列：103 = F1 基本型
 │    └───────────── 系列：F = 通用型
 └────────────────── 品牌：STMicroelectronics
```

本笔记统一使用 **STM32F103C8T6**。

买核心板时要注意：

- `C8T6`：64 KB Flash。
- `CBT6`：128 KB Flash。
- `T6`：LQFP 封装。
- 同型号不同封装引脚排列不同，查手册时必须看对应封装。

### 数据手册和参考手册

| 对比项 | 数据手册（Datasheet） | 参考手册（Reference Manual） |
|--------|------------------------|-------------------------------|
| 主要内容 | 电气特性、引脚定义、封装尺寸、复用功能 | 外设工作原理、寄存器定义、时钟和中断细节 |
| 典型页数 | 约 100 页 | 约 1000+ 页 |
| 什么时候查 | 画原理图、找引脚功能、确认电压范围 | 写驱动、理解外设行为、查寄存器位 |
| 典型问题 | `PC13` 能不能承受 5 V？某个引脚能不能做 ADC？ | TIM2 的 PWM 模式 1 和模式 2 有什么区别？ |

新手常见误区：下载了参考手册却想找引脚定义。**引脚定义通常在数据手册的 Pinouts and pin descriptions 章节。**

### 时钟树

常见 STM32F103C8T6 核心板使用 8 MHz 外部晶振，经 PLL 倍频到 72 MHz：

```text
HSE 8 MHz
└── PLL x9
    └── SYSCLK = 72 MHz
        ├── AHB Prescaler /1  -> HCLK  = 72 MHz
        ├── APB1 Prescaler /2 -> PCLK1 = 36 MHz
        └── APB2 Prescaler /1 -> PCLK2 = 72 MHz
```

STM32F1 常见总线和外设归属：

| 总线 | 时钟限制 / 常见值 | 常见外设 |
|------|-------------------|----------|
| AHB | 常见 72 MHz | DMA、SRAM、Flash 接口、总线矩阵 |
| APB1 | 最高 36 MHz | TIM2/3/4、USART2/3、SPI2、I2C1/2 |
| APB2 | 最高 72 MHz | GPIOA/B/C、AFIO、USART1、SPI1、ADC1/2、TIM1 |

**定时器时钟特例**：当 APBx 预分频不等于 1 时，该总线上的定时器时钟 = `PCLKx x 2`。

例如：

```text
APB1 Prescaler = /2
PCLK1 = 36 MHz
TIM2/3/4 时钟 = 36 MHz x 2 = 72 MHz
```

所以 TIM2/3/4 的定时计算不能直接拿 36 MHz 当时钟源。

## CubeMX 配置

### 工具链关系

| 工具 | 作用 | 备注 |
|------|------|------|
| STM32CubeMX | 图形化配置芯片、引脚、时钟、外设，生成初始化代码 | CubeIDE 内置 CubeMX 功能 |
| STM32CubeIDE | 写代码、编译、烧录、调试 | 内置 GCC、GDB、CubeMX 配置界面 |
| ST-Link / DAP-Link | SWD 烧录调试器 | 连接 SWDIO、SWCLK、GND、3V3 参考电平 |
| OpenOCD / GDB | 命令行调试链路 | CubeIDE 内部也会使用类似 GDB 调试流程 |

本笔记使用 CubeIDE。课程如果使用 MDK-Keil，HAL 代码和 CubeMX 外设配置逻辑仍然通用。

### 新建工程流程

#### 1. 选择芯片

1. 打开 CubeMX。
2. `File` -> `New` -> `STM32 Project`。
3. 在 `Commercial Part Number` 输入 `STM32F103C8T6`。
4. 双击选中芯片，点击 `Next`。
5. 填写工程名，点击 `Finish`。

#### 2. 配置调试口

1. 打开 `Pinout & Configuration`。
2. `System Core` -> `SYS`。
3. `Debug` 选择 **Serial Wire**。

这一步非常重要。如果不配置，SWD 调试口可能被普通 GPIO 占用，后续 ST-Link 无法稳定烧录或调试。

#### 3. 配置 HSE 和时钟树

1. `System Core` -> `RCC`。
2. `High Speed Clock (HSE)` 选择 `Crystal/Ceramic Resonator`。
3. 打开 `Clock Configuration`。
4. `PLL Source Mux` 选择 `HSE`。
5. `PLL Mul` 设置为 `x9`。
6. 确认：

```text
SYSCLK = 72 MHz
HCLK   = 72 MHz
PCLK1  = 36 MHz
PCLK2  = 72 MHz
```

注意：8 MHz 是常见 F103 核心板配置，实际项目要以板载晶振为准。

#### 4. 配置 PC13 输出

1. 回到 `Pinout & Configuration`。
2. 点击 `PC13`。
3. 选择 `GPIO_Output`。
4. 如需更清晰，可在 `System Core` -> `GPIO` 中给 `PC13` 设置 `User Label`，例如 `LED_Pin`。

#### 5. 生成代码

1. `Project Manager` -> `Project`。
2. `Toolchain / IDE` 选择 `STM32CubeIDE`。
3. `Code Generator` 中建议勾选：

```text
Generate peripheral initialization as a pair of .c/.h files per peripheral
```

4. 点击 `GENERATE CODE`。

### 生成的项目结构

```text
工程根目录/
├── Core/
│   ├── Inc/
│   │   └── main.h             # 全局宏、函数声明、用户声明
│   └── Src/
│       ├── main.c             # 主函数和用户主循环
│       ├── gpio.c             # GPIO 初始化
│       ├── stm32f1xx_it.c     # 中断服务函数
│       └── stm32f1xx_hal_msp.c # HAL 底层 MSP 初始化
├── Drivers/                   # CMSIS 和 HAL 库源码，通常不要改
├── Debug/                     # 编译输出目录
└── project.ioc                # CubeMX 配置文件，双击可重新打开配置界面
```

### USER CODE 保护机制

CubeMX 重新生成代码时，**只会保留写在 `USER CODE BEGIN` 和 `USER CODE END` 之间的内容**。

> 代码性质：可直接移植的最小实验框架，变量名需按 CubeMX 实际生成结果调整。

```c
/* USER CODE BEGIN 0 */
// 自己写的函数、宏、静态变量等
/* USER CODE END 0 */

// 写在 USER CODE 区域外面的代码，重新生成后可能被覆盖
```

常见 USER CODE 区域：

| 区域 | 位置 | 适合放什么 |
|------|------|------------|
| `Includes` | 文件顶部 | 自己额外添加的头文件 |
| `PV` | 私有变量区 | 全局变量、状态变量 |
| `0` | `main()` 前 | 私有函数、工具函数 |
| `1` | `main()` 内，`HAL_Init()` 前 | 极少使用 |
| `2` | 外设初始化后，进入 `while(1)` 前 | 用户初始化代码 |
| `WHILE` | `while(1)` 前 | 主循环前的准备代码 |
| `3` | `while(1)` 内 | 主循环逻辑 |
| `4` | 文件末尾 | 回调函数 |

## HAL 函数 / API

### `HAL_GPIO_WritePin`

函数：

```c
void HAL_GPIO_WritePin(GPIO_TypeDef *GPIOx, uint16_t GPIO_Pin, GPIO_PinState PinState);
```

作用：

- 调用后，HAL 会把指定 GPIO 引脚输出为高电平或低电平。
- 不调用时，LED、蜂鸣器、片选等输出引脚不会按业务逻辑变化。
- 适合明确设置某个引脚状态，例如点亮 LED、拉高片选、关闭蜂鸣器。

参数说明：

| 参数 | 说明 |
|------|------|
| `GPIOx` | 端口基地址指针，例如 `GPIOA`、`GPIOB`、`GPIOC` |
| `GPIO_Pin` | 引脚位掩码，例如 `GPIO_PIN_0`、`GPIO_PIN_13` |
| `PinState` | 输出状态：`GPIO_PIN_SET` 或 `GPIO_PIN_RESET` |

注意：

- `GPIO_PIN_0` 不是数字 0，而是位掩码 `0x0001`。
- `GPIO_PIN_13` 是第 13 位的位掩码。
- 多个引脚可以用 `|` 组合，例如 `GPIO_PIN_0 | GPIO_PIN_1`。
- `GPIOA`、`GPIOB` 这类符号来自芯片头文件中的外设基地址定义，不是 CubeMX 随便生成的普通变量。

### `HAL_GPIO_TogglePin`

函数：

```c
void HAL_GPIO_TogglePin(GPIO_TypeDef *GPIOx, uint16_t GPIO_Pin);
```

作用：

- 调用后，指定引脚输出状态会翻转：高变低、低变高。
- 不调用时，引脚会保持原来的输出状态。
- 适合 LED 闪烁、状态指示等只关心“翻转”的场景。

```c
HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);
```

对于常见 PC13 板载 LED：

- 如果 LED 是低电平点亮，`GPIO_PIN_RESET` 代表亮。
- `HAL_GPIO_TogglePin()` 不关心亮灭逻辑，只负责翻转电平。

### `HAL_Delay`

函数：

```c
void HAL_Delay(uint32_t Delay);
```

作用：

- 调用后，CPU 会阻塞等待指定毫秒数。
- 不调用时，循环会高速执行，LED 闪烁等现象可能快到看不出来。
- 适合入门实验和低频简单等待，不适合复杂实时任务。

```c
HAL_Delay(500);  // 延时 500 ms
```

参数说明：

| 参数 | 说明 |
|------|------|
| `Delay` | 延时时间，单位 ms，类型为 `uint32_t` |

`HAL_Delay()` 依赖 SysTick 提供的 1 ms 时基。CubeMX 默认会生成 SysTick 中断，`SysTick_Handler()` 中会调用 `HAL_IncTick()`，从而让 HAL 的毫秒计数递增。

简化理解：

```text
SysTick 每 1 ms 中断一次
-> HAL_IncTick()
-> uwTick++
-> HAL_GetTick() 返回当前毫秒数
-> HAL_Delay() 循环等待时间差达到目标值
```

工程注意：`HAL_Delay()` 是阻塞函数，不适合放在中断服务函数中，也不适合复杂实时任务里大量使用。

## 示例代码

### PC13 板载 LED 闪烁

在 `Core/Src/main.c` 的 `while (1)` 内，放到 `USER CODE BEGIN 3` 区域：

> 代码性质：可直接移植的最小实验框架，变量名需按 CubeMX 实际生成结果调整。

```c
/* USER CODE BEGIN WHILE */
while (1)
{
  /* USER CODE END WHILE */

  /* USER CODE BEGIN 3 */
  HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);
  HAL_Delay(500);
}
/* USER CODE END 3 */
```

现象：

- LED 每 500 ms 翻转一次。
- 一个完整亮灭周期约 1 s。
- 如果板载 LED 是低电平点亮，则电平低时亮、电平高时灭，但闪烁效果不受影响。

### 编译和烧录验证

1. 点击工具栏 `Build`。
2. 确认 `0 errors`。
3. 接入 ST-Link / DAP-Link。
4. 点击 `Run` 或 `Debug`。
5. 板载 LED 闪烁，说明工程、时钟、GPIO、烧录链路基本打通。

## 代码执行流程

```text
上电复位
↓
HAL_Init() 初始化 HAL 和 SysTick
↓
SystemClock_Config() 配置系统时钟
↓
MX_GPIO_Init() 配置 PC13 输出
↓
进入 while(1)
↓
HAL_GPIO_TogglePin() 翻转 PC13 电平
↓
HAL_Delay(500) 阻塞等待 500 ms
↓
循环执行，LED 周期闪烁
```

## 常见错误

| 问题 | 常见原因 | 解决方法 |
|------|----------|----------|
| 烧录失败 | `SYS -> Debug` 没选 `Serial Wire` | 回 CubeMX 配置 SWD，并重新生成代码 |
| 烧录后程序不跑 | `BOOT0` 悬空或被拉高 | 正常运行时 `BOOT0` 通过 10 kΩ 下拉到 GND |
| 重新生成代码后用户代码丢失 | 代码写在 USER CODE 区域外 | 所有用户代码放在 `USER CODE BEGIN/END` 之间 |
| LED 不亮 | PC13 未配置为 `GPIO_Output` | 检查 CubeMX 的 GPIO 配置 |
| LED 逻辑反了 | 板载 LED 为低电平点亮 | 用翻转验证，不要只用“高电平=亮”的经验判断 |
| 时钟不是 72 MHz | HSE/PLL 配错，或板子不是 8 MHz 晶振 | 检查 RCC 和 Clock Configuration |
| 定时器时间算错 | 忽略 APB 定时器 x2 规则 | 确认 TIMx_CLK，不只看 PCLKx |
| 编译路径异常 | 工具链或工程路径含中文、空格、特殊符号 | 新手阶段建议使用纯英文路径 |
| 外设没有反应 | 外设时钟没开或 CubeMX 没生成初始化 | 确认 `MX_GPIO_Init()` 等初始化函数被调用 |

---

## 调试方法

### 最小硬件检查

1. 确认核心板供电正常，3V3 和 GND 电压正确。
2. 确认 ST-Link / DAP-Link 与板子 **共地**。
3. 确认连接 `SWDIO`、`SWCLK`、`GND`，必要时接 `3V3` 作为参考电平。
4. 确认 `BOOT0` 为低电平。
5. 确认 `NRST` 没有被外部电路持续拉低。

### CubeIDE 调试思路

- 先在 `main()` 第一行打断点，确认程序能进入主函数。
- 再在 `MX_GPIO_Init()` 后打断点，确认 GPIO 初始化执行过。
- 最后在 `HAL_GPIO_TogglePin()` 处单步，观察 LED 是否翻转。
- 如果能进断点但 LED 不亮，优先查 GPIO 引脚、LED 有效电平和板子原理图。
- 如果不能进断点，优先查 SWD、BOOT0、供电和时钟配置。

### OpenOCD / GDB 的理解

CubeIDE 的图形化调试背后，本质上也是：

```text
GDB
-> 调试服务器（ST-LINK GDB Server 或 OpenOCD）
-> ST-Link / DAP-Link
-> SWD
-> STM32 芯片
```

理解这条链路后，后面用 VS Code、OpenOCD、`arm-none-eabi-gdb` 调试时就不会觉得陌生。

## 工程意义

这一节不是只为了点亮 LED，而是为了打通嵌入式开发的最小闭环：

```text
选芯片
-> 配时钟
-> 配引脚
-> 生成工程
-> 写用户代码
-> 编译
-> 烧录
-> 调试
-> 观察硬件现象
```

后面的 GPIO、串口、ADC、DMA、定时器、本质上都是在这个闭环上增加外设配置和业务逻辑。

掌握本节后，至少要能回答：

- 我用的具体芯片型号是什么？
- 这个引脚能不能做目标功能，去哪里查？
- 代码为什么要写在 USER CODE 区域？
- HAL 函数背后大概在操作什么？
- 72 MHz 是怎么从 8 MHz 晶振来的？
- 烧录失败时先查硬件链路还是先改代码？

## 易混淆点

| 容易混淆 | 正确理解 |
|----------|----------|
| ARM 和 STM32 | ARM 设计内核，ST 把内核和外设做成 STM32 芯片 |
| 数据手册和参考手册 | 数据手册查引脚和电气参数，参考手册查外设和寄存器 |
| `GPIO_PIN_13` 和数字 13 | `GPIO_PIN_13` 是位掩码，不是普通整数编号 |
| HSE 和 HSI | HSE 是外部高速晶振，HSI 是内部 RC 时钟 |
| PCLK 和 TIMx_CLK | APB 分频不为 1 时，定时器时钟可能是 PCLK 的 2 倍 |
| CubeMX 和 CubeIDE | CubeMX 负责配置和生成代码，CubeIDE 集成了 CubeMX 并负责编译调试 |
| HAL 和裸寄存器 | HAL 封装寄存器操作，裸寄存器直接读写硬件地址 |
| 高电平和 LED 亮 | 很多 F103 核心板 PC13 LED 是低电平点亮 |
| 烧录和调试 | 烧录只是写程序进 Flash，调试还能下断点、单步、看变量和寄存器 |

## 我的理解

STM32 入门第一步不是急着背外设，而是先把“工程怎么跑起来”这条链路搞清楚。

我现在的理解是：

- **核心板**提供最小可运行硬件。
- **数据手册**告诉我引脚和电气限制。
- **参考手册**告诉我外设内部怎么工作。
- **CubeMX**帮我把时钟、引脚、外设初始化先生成出来。
- **HAL 库**让我先用函数表达硬件操作，不用一上来就硬啃寄存器。
- **USER CODE 区域**是我和 CubeMX 分工的边界。
- **SWD 调试**是工程救命线，一定不能乱禁用。

这节课真正要留下的感觉是：以后遇到任何外设，都可以按同一套路径拆解：

```text
先看硬件连接
-> 查手册确认引脚和限制
-> CubeMX 配时钟和外设
-> 找 HAL API
-> 写最小代码验证
-> 编译烧录
-> 用现象和调试工具反推问题
```
