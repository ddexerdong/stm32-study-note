## [6] 核心板、面包板、扩展板

### 知识点
- 核心板 = STM32 芯片 + 晶振 + 复位电路 + LDO 稳压，所有 GPIO 通过排针引出
- 面包板 = 免焊接实验板，利用内部金属弹片连通电路
- 扩展板 = 传感器、驱动等模块，通过杜邦线连接到核心板

### STM32F103C8T6 核心板关键引脚

| 引脚 | 功能 | 注意事项 |
|------|------|---------|
| 3V3 | 3.3V 电源输出 | 给 STM32 和 3.3V 外设供电 |
| 5V | 5V 电源输入/输出 | USB 供电时输出 5V；也可外接 5V 给板子供电 |
| GND | 地 | **所有外设必须和 STM32 共地** |
| PA9 / PA10 | USART1 TX / RX | 串口通信、USB-TTL 烧录 |
| SWDIO / SWCLK | 调试接口 | 接 ST-Link / DAP 烧录器 |
| BOOT0 | 启动选择 | 通过 10kΩ 电阻接 GND = 从 Flash 启动（正常工作模式） |
| NRST | 复位 | 低电平复位，内部已有上拉 |
| PC13 | 板载 LED | 大部分 C8T6 核心板 LED 接此引脚（低电平点亮） |

### 面包板内部连接

```
俯视图：
┌────────────────────────────────────┐
│ + ───────────────────────────── + │ ← 横向连通（电源轨）
│ - ───────────────────────────── - │ ← 横向连通（地轨）
├────────────────────────────────────┤
│ │ │ │ │ │ │ │ │ │  ...  │ │ │ │ │ │ ← 纵向 5 孔连通
├────────────────────────────────────┤  ← 中间沟槽（两侧不通）
│ │ │ │ │ │ │ │ │ │  ...  │ │ │ │ │ │ ← 纵向 5 孔连通
├────────────────────────────────────┤
│ + ───────────────────────────── + │
│ - ───────────────────────────── - │
└────────────────────────────────────┘

关键约束：中间横向沟槽两侧的孔不互通，芯片要跨沟槽插。
每一列纵向 5 个孔是通的，但上下半区不互通。
```

### 易错点
- 杜邦线分公母：核心板排针用母对母杜邦线，面包板用公对公杜邦线
- 杜邦线内部断裂外表看不出来 → 接触不良时优先换线排查
- 面包板使用前用万用表蜂鸣档验证连通性（特别是老旧面包板）

## [7-1] STM32 命名规则与手册

### 命名规则

```
STM32 F 103 C 8 T 6
 │     │  │  │ │ │ └─ 温度范围：6 = 工业级（-40~85℃）
 │     │  │  │ │ └─── 封装：T = LQFP
 │     │  │  │ └───── Flash 容量：8 = 64KB, B = 128KB
 │     │  │  └─────── 引脚数：C = 48pin, R = 64pin
 │     │  └────────── 子系列：103 = F1 基本型
 │     └──────────── 系列：F = 通用型
 └────────────────── 品牌：STMicroelectronics
```

本笔记统一使用 **STM32F103C8T6**：72MHz / 64KB Flash / 20KB RAM / 48pin。

### 两份手册的区别

| | 数据手册（Datasheet） | 参考手册（Reference Manual） |
|--|---------------------|--------------------------|
| 内容 | 电气特性、引脚定义、封装尺寸 | 外设功能描述、寄存器定义 |
| 页数 | ~100 页 | ~1100 页 |
| 什么时候查 | 画原理图、找引脚功能、确认电压范围 | 编程时需要了解外设工作原理 |
| 典型问题 | "PC13 能不能承受 5V？" | "TIM2 的 PWM 模式 1 和模式 2 区别是啥？" |

> 新手常犯错误：下载了参考手册当数据手册用，找不到引脚定义在哪。引脚定义在数据手册的 Pinouts and pin descriptions 章节。

### 易错点
- 买芯片/核心板注意后缀：C8T6 = 64KB Flash，CBT6 = 128KB Flash。程序超过 64KB 时 C8T6 放不下。
- 同型号不同封装（T6 = LQFP、U6 = VFQFPN）引脚排列不同，查手册要对应封装。

## [7-2] ARM 内核、寄存器与 HAL 库

### ARM 内核和 STM32 的关系

ARM 公司设计 Cortex-M3 处理器内核（指令集、NVIC 中断控制器、SysTick 等）。ST 公司购买授权，在 Cortex-M3 外围添加 Flash、RAM、GPIO、UART、ADC 等外设，封装成一颗 STM32F103C8T6 芯片。

```
Cortex-M3 内核 (ARM 设计)
    ├── NVIC（嵌套向量中断控制器）
    ├── SysTick（24 位系统定时器）
    └── CPU 核心（取指、译码、执行）

STM32F103C8T6 (ST 设计)
    = Cortex-M3 内核
    + 64KB Flash（程序存储器）
    + 20KB SRAM（运行内存）
    + GPIOA/B/C、USART1/2/3、SPI1/2、I2C1/2
    + TIM1/2/3/4、ADC1/2、DMA...
```

### 寄存器是什么

芯片内部有一组**有特殊功能的存储单元**，每个有固定地址，写入不同的值硬件就有不同的行为。这就是寄存器。

```c
// GPIOB 的 ODR（Output Data Register，输出数据寄存器）
// 地址：0x4001 0C0C
*(volatile uint32_t *)0x40010C0C = 0x0001;  // PB0=高，其余=低
*(volatile uint32_t *)0x40010C0C = 0x0000;  // 全部=低
```

`volatile` 关键字告诉编译器：这个地址的值可能被硬件改变，每次都要真实读写，不能优化掉。

### HAL 库的定位

直接操作寄存器有三个问题：地址难记、位操作容易出错、代码不可移植。HAL（Hardware Abstraction Layer，硬件抽象层）把寄存器操作封装成函数：

```c
// 寄存器写法（需要知道地址、位定义）：
*(volatile uint32_t *)0x40010C0C |= (1 << 0);  // PB0 置高

// HAL 库写法（只需知道端口和引脚名）：
HAL_GPIO_WritePin(GPIOB, GPIO_PIN_0, GPIO_PIN_SET);
```

HAL 库函数命名规则：`HAL_外设_操作()`。例如 `HAL_GPIO_WritePin`、`HAL_UART_Transmit`、`HAL_ADC_Start`。

### HAL 库函数参数说明

以 `HAL_GPIO_WritePin` 为例看一下 HAL 函数的一般形式：

```c
void HAL_GPIO_WritePin(GPIO_TypeDef *GPIOx, uint16_t GPIO_Pin, GPIO_PinState PinState);

// 参数 1：GPIOx  — 哪个 GPIO 端口（GPIOA、GPIOB、GPIOC...）
//                  类型是 GPIO_TypeDef*，是 CubeMX 生成的全局变量
// 参数 2：GPIO_Pin — 该端口的哪个引脚（GPIO_PIN_0 ~ GPIO_PIN_15）
//                   这些是宏，定义为 0x0001、0x0002、0x0004...（位掩码）
// 参数 3：PinState — 目标状态
//                   GPIO_PIN_SET   = 高电平（3.3V）
//                   GPIO_PIN_RESET = 低电平（0V）
```

> 要了解一个 HAL 函数的参数和返回值，最直接的方法是在 CubeIDE 里 Ctrl+Click 点击函数名，跳转到它的声明处查看注释。

### 易错点
- HAL 库函数参数很多是位掩码宏（如 GPIO_PIN_0 = 0x0001），不要误以为是引脚编号
- 调用 HAL 函数前，对应外设必须已经在 CubeMX 里配置并使能了时钟，否则硬件不响应

## [8] CubeMX 新建工程与烧录验证

### 工具链

| 工具 | 做什么 | 关系 |
|------|--------|------|
| STM32CubeMX | 图形化配引脚、时钟、外设 → 生成初始化代码 | CubeIDE 内置 |
| STM32CubeIDE | 写代码 + 编译(GCC) + 烧录 + 调试(GDB) | 主力工具 |

本笔记全部使用 CubeIDE（课程原版用 MDK-Keil，HAL 库和外设配置逻辑完全通用）。

### 新建工程完整流程

**第一步：选芯片**
1. 打开 CubeIDE → File → New → STM32 Project
2. Commercial Part Number 输入 `STM32F103C8T6` → 双击选中 → Next → 填工程名 → Finish

**第二步：配置调试口**
3. System Core → SYS → Debug → **Serial Wire**

这一步如果不配（默认是 Disable），SWD 调试口会被禁用，ST-Link 就烧不进去程序了。CubeIDE 会弹出警告，不能忽略。

**第三步：配置时钟树**
4. 打开 Clock Configuration 标签页
5. HSE 选 `Crystal/Ceramic Resonator`（外部 8MHz 晶振）
6. PLL Source Mux 选 HSE
7. PLL Mul 设为 `×9`
8. 按回车让工具自动计算 → 确认最终值：

```
HSE (8MHz) → PLL (×9) → SYSCLK = 72MHz
                            ├─ AHB Prescaler: /1 → HCLK = 72MHz
                            ├─ APB1 Prescaler: /2 → PCLK1 = 36MHz
                            └─ APB2 Prescaler: /1 → PCLK2 = 72MHz
```

各总线挂载的外设速查：

| 总线 | 时钟 | 挂载的外设 |
|------|------|----------|
| AHB | 72MHz | GPIO、DMA |
| APB1 | 36MHz | TIM2~TIM7、USART2/3、SPI2/I2C2 |
| APB2 | 72MHz | TIM1/8、USART1、SPI1、ADC1/2 |

> ⚠️ 定时器时钟特例：当 APBx 预分频 ≠ 1 时，该总线上的定时器时钟 = PCLKx × 2。
> APB1 预分频 = /2 → TIM2/3/4 时钟 = 36MHz × 2 = 72MHz，不是 36MHz。

**第四步：配置一个 GPIO 作为验证**
9. Pinout 标签 → 点 PC13 → 选 GPIO_Output

**第五步：生成代码**
10. Project Manager → Toolchain/IDE 选 STM32CubeIDE
11. 勾选 "Generate peripheral initialization as a pair of .c/.h files"
12. 点 GENERATE CODE

### 生成的项目结构

```
工程根目录/
├── Core/
│   ├── Inc/
│   │   └── main.h          ← 全局声明
│   └── Src/
│       ├── main.c          ← ⭐ 用户代码写在这里
│       └── stm32f1xx_it.c  ← 中断服务函数
├── Drivers/                ← HAL 库源码，不要修改
└── project.ioc             ← CubeMX 配置文件（双击重新打开配置界面）
```

### 用户代码保护机制

CubeMX 重新生成代码时，**只保留写在特定注释对之间的代码**：

```c
/* USER CODE BEGIN 0 */    ← 标记开始
// 这里的内容保留
/* USER CODE END 0 */      ← 标记结束

// 写在注释外面的代码 → 重新生成后全部丢失！
```

USER CODE 区域有多种，对应 main.c 的不同位置：

| 区域 | 位置 | 用途 |
|------|------|------|
| Includes | 文件顶部 | 添加自己的 #include |
| PV | 变量区 | 全局变量 |
| 0 | main() 前 | 用户私有函数 |
| 1 | main() 内最前 | HAL_Init 之前 |
| 2 | 外设初始化后 | 用户初始化代码 |
| WHILE | while(1) 内 | 主循环 |
| 4 | 文件末尾 | 回调函数 |

### 烧录验证

在 main.c 的 while(1) 中添加：

```c
/* USER CODE BEGIN WHILE */
while (1)
{
    HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);  // 翻转 PC13
    HAL_Delay(500);                            // 延时 500ms
    /* USER CODE END WHILE */
}
```

工具栏点 🔨 Build → 0 errors → 点 ▶️ Run → 板载 LED 闪烁 = 环境搭建成功。

### 易错点
- Debug 口未配 Serial Wire → 烧录失败
- BOOT0 悬空（未接地）→ 烧录后程序不跑
- CubeMX 重新生成 → 未放在 USER CODE 区域内的代码全部丢失
- 安装路径含中文 → 编译报错
