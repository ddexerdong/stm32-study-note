## 核心概念

### 知识地图

| 名词 | 工程含义 | 常见位置 |
|------|----------|----------|
| I2C 传感器 | 通过 I2C 读写内部寄存器的外部芯片 | `[32-1]` 到 `[34-1]` |
| 设备地址 | I2C 总线上的从设备地址 | 模块手册 |
| 设备 ID | 用于确认芯片型号或通信是否正常的寄存器值 | 初始化前 |
| 寄存器地址 | 芯片内部功能单元的编号 | 驱动文件 |
| 配置寄存器 | 设置采样率、量程、模式、使能等参数 | 初始化函数 |
| 数据寄存器 | 存放采样结果的寄存器 | 读取函数 |
| 连续读 | 从起始寄存器开始一次读取多个字节 | 传感器数据 |
| 原始值 | 未换算的寄存器数据 | 调试阶段 |
| FIFO | 先入先出缓冲区，常用于连续采样数据 | MAX30102 |
| ToF | Time of Flight，飞行时间测距思路 | VL53L0X |
| 姿态原始数据 | 加速度、角速度、温度等寄存器读数 | MPU6050 |

### 常用 HAL API

| API / 宏 | 作用 | 常见用法 |
|----------|------|----------|
| `HAL_I2C_IsDeviceReady()` | 探测设备地址是否 ACK | 上电检测 |
| `HAL_I2C_Mem_Read()` | 从指定寄存器读数据 | 读 ID、读采样值 |
| `HAL_I2C_Mem_Write()` | 向指定寄存器写数据 | 配置传感器 |
| `HAL_I2C_Master_Transmit()` | 发送裸命令或地址序列 | 特殊设备流程 |
| `HAL_I2C_Master_Receive()` | 接收裸数据 | 特殊设备流程 |
| `HAL_UART_Transmit()` | 串口打印原始值或错误码 | 调试输出 |

## 本质理解

前一章已经把 I2C 总线基础讲清楚了。本章的重点是：**传感器驱动就是按手册读写一组外部寄存器。**

通用套路是：

```text
确认供电和地址 ACK
-> 读设备 ID
-> 写初始化配置
-> 等待数据就绪
-> 连续读取数据寄存器
-> 拼接原始值
-> 按手册或课程公式换算
-> 串口或 OLED 显示
```

MAX30102、VL53L0X、MPU6050 的完整初始化参数、算法公式和库文件来源，PDF 和当前笔记都不足以完全支撑，不能写成确定事实。

## 工作流程 / 原理

### 通用传感器 bring-up 流程

```text
I2C 地址扫描
-> HAL_I2C_IsDeviceReady()
-> 读取 WHO_AM_I / ID / Model ID
-> 对照期望值
-> 写配置寄存器
-> 读取状态寄存器
-> 读取数据寄存器
-> 打印原始值
-> 再做换算或算法
```

如果 ID 都读不到，不要继续调算法。先回到供电、共地、上拉、地址、CubeMX。

### MAX30102 学习重点

MAX30102 属于心率血氧方向的光学传感器。学习时先不要直接跳到“心率/血氧算法”，先确认：

- I2C 地址是否 ACK。
- ID 或版本寄存器是否能读到。
- FIFO 或数据寄存器是否有变化。
- LED 驱动、采样参数、FIFO 配置来自哪里。

> 视频待核对：MAX30102 的 I2C 地址、ID 寄存器、FIFO 读取方式、LED/采样配置、心率血氧算法和库文件来源。

### VL53L0X 学习重点

VL53L0X 是激光 ToF 测距类传感器。学习时先按“库和寄存器流程”看，不要自己编造完整测距初始化：

- 设备是否 ACK。
- ID / Model ID 是否正确。
- 是否需要官方或课程提供的初始化序列。
- 测距结果寄存器或库函数返回值是否可信。

> 视频待核对：VL53L0X 的 I2C 地址、初始化库来源、测距启动流程、数据就绪判断和距离换算口径。

### MPU6050 学习重点

PDF 第 43 章能支撑 MPU6050 作为 I2C 传感器读取加速度、角速度和温度原始数据的思路。入门阶段先看：

- WHO_AM_I 是否能读到。
- 电源管理寄存器是否配置到工作状态。
- 加速度、角速度、温度原始寄存器是否能连续读。
- 原始值如何按量程换算。

PDF 提到 MPU6050 更复杂的 DMP 姿态解算，但本批只写基础学习框架，不展开完整姿态算法。

> 视频待核对：课程 `[34-1]` 使用的 MPU6050 地址、寄存器宏、量程配置、原始值换算公式和是否涉及 DMP。

## 调试方法

按指定顺序排查：

### 供电

1. 确认传感器模块供电电压。
2. 不确定模块是否 5 V 容忍时，优先按 3.3 V 逻辑处理。
3. 模块发热、芯片烫手时立即断电检查。

### 共地

1. STM32、传感器模块、外部电源必须共地。
2. 面包板供电轨可能断开，先确认 GND 连通。

### 上拉电阻

1. SCL/SDA 必须能被上拉到高电平。
2. 多个模块都带上拉时，总等效电阻可能过小，要观察波形。
3. 空闲低电平通常说明接线、短路或模式配置有问题。

### I2C 地址

1. 先扫描地址，不要直接相信网上示例。
2. 区分 7 位地址和 HAL 左移后的地址。
3. 同一总线上多个设备地址不能冲突。

### CubeMX 配置

1. I2C 外设是否启用。
2. 引脚是否与硬件一致。
3. 速度是否过高。
4. 如果使用 INT 脚，EXTI 是否单独配置。

### HAL API 返回值

1. 每次 `HAL_I2C_Mem_Read()` / `HAL_I2C_Mem_Write()` 都检查返回值。
2. 先确认 `HAL_I2C_IsDeviceReady()` 通过。
3. 失败时记录寄存器地址、设备地址和错误阶段。

### 逻辑分析仪 / 串口打印

1. 串口打印扫描到的地址、读到的 ID、HAL 返回值。
2. 逻辑分析仪看 START、地址、ACK、寄存器地址、数据。
3. 如果地址有 ACK 但 ID 不对，重点查寄存器地址、读写流程和模块型号。

### 业务逻辑

1. 先显示原始字节。
2. 再拼接有符号/无符号原始值。
3. 最后才做心率/血氧/距离/姿态等算法。
4. 算法异常时先确认原始数据是否稳定。

## 工程意义

I2C 传感器章节的价值不是把某个模块代码背下来，而是建立一种可迁移的阅读方式：

```text
地址
-> ID
-> 配置
-> 状态
-> 数据
-> 换算
-> 显示
```

以后换成别的 I2C 传感器，我也能按这条路线拆解，而不是从网上复制一整包库后不知道哪里出错。

---

## 易混淆点

| 容易混淆 | 正确理解 |
|----------|----------|
| I2C 地址和寄存器地址 | 地址选中外部芯片，寄存器地址选中芯片内部功能 |
| 读到 ACK 和读到正确数据 | ACK 只说明设备回应，不代表寄存器和算法都对 |
| 原始值和物理量 | 原始值是寄存器数据，物理量需要按手册换算 |
| 初始化参数和算法公式 | 未经视频/手册确认不能写成确定事实 |
| MAX30102 原始数据和心率血氧 | 心率血氧需要算法处理，不是读一个寄存器就得到 |
| VL53L0X 原始流程和距离结果 | 测距初始化和数据就绪流程依赖库或手册 |
| MPU6050 原始数据和姿态角 | 姿态角通常还需要滤波、融合或 DMP，不等于直接读寄存器 |

---

## 我的理解

我现在把 I2C 传感器理解成“挂在 I2C 总线上的小寄存器芯片”。STM32 不是直接问它“现在心率多少、距离多少、姿态多少”，而是按地址和寄存器一步步读出原始信息。

以后调 MAX30102、VL53L0X、MPU6050，我会先按这个顺序来：

```text
供电
-> 共地
-> 上拉
-> 地址 ACK
-> 读 ID
-> 写配置
-> 读原始数据
-> 串口/OLED 显示
-> 再看换算和算法
```

如果 ID 都读不到，我不会去改算法；如果原始数据不稳定，我也不会急着改显示格式。

```c
uint8_t MAX30102_CheckDevice(void)
{
    uint8_t id = 0;

    /* 视频待核对：设备 ID 寄存器地址和期望值。 */
    if (HAL_I2C_Mem_Read(&hi2c1, MAX30102_ADDR, MAX30102_ID_REG,

    {
        return 0;
    }

    return 1;
}

uint8_t MAX30102_ReadRaw(uint32_t *red, uint32_t *ir)
{
    /* 视频待核对：FIFO 数据格式和字节拼接方式。 */
    (void)red;
    (void)ir;
    return 0;
}
```

### 调试方法

- 先读设备 ID，不要一上来调算法。
- 再看 FIFO 是否有原始数据变化。
- 手指接触、环境光和供电都会影响原始数据。

### 常见坑

- I2C 能 ACK 但 FIFO 没配置。
- 原始数据字节顺序拼错。
- 把原始红光/红外值直接当心率血氧。

- 先确认 I2C ACK，再看库初始化返回值。
- 初始化失败时不要直接读距离。
- 记录每一步返回值，方便定位是通信失败还是配置失败。

### 常见坑

- 跳过库初始化直接读距离。
- 把数据未就绪当成测距为 0。
- I2C 地址和库里默认地址不一致。
