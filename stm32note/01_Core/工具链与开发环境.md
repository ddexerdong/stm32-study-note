# 工具链与开发环境

> 能力定位：建立“配置、编译、下载、调试”完整链路。
>
> 原始来源：[[00_课程环境与工具链]]。

## 工具分工

| 工具 / 文件 | 工程作用 |
|---|---|
| STM32CubeMX / `.ioc` | 配置芯片、时钟、引脚、外设并生成初始化代码 |
| MDK / Keil | 编译、链接、下载和调试 |
| Device Pack | 让 MDK 认识具体芯片、启动文件和调试描述 |
| DAP / CMSIS-DAP / SWD | CMSIS-DAP 是调试器协议实现，SWD 是芯片侧两线调试接口，用于下载、断点、单步和变量观察 |
| USB-TTL / Bootloader | 串口下载或串口调试 |

## 推荐验证顺序

```text
板子供电与共地
-> MDK 能识别目标芯片
-> 工程能编译
-> DAP 能识别芯片
-> 能下载并复位运行
-> 能进入 main 并单步
-> 再配置具体外设
```

## CubeMX 与用户代码

- CubeMX 负责生成 `MX_GPIO_Init()`、`MX_USARTx_UART_Init()` 等初始化函数。
- 业务代码放在 USER CODE 区域或独立 BSP 文件，避免重新生成时丢失。
- 工程路径、Pack、下载器和调试口问题，应先于 HAL API 排查。

## 知识地图

| 名词 | 工程含义 |
|---|---|
| 编译 | 把每个 C 文件变成目标文件 |
| 链接 | 按链接脚本把代码和数据放入 Flash/SRAM 地址 |
| Pack | 为 MDK 提供芯片、启动文件和调试描述 |
| SWD | 使用 SWDIO/SWCLK 的下载调试接口 |
| Bootloader | 芯片系统存储器中的下载程序 |

## 本质理解

工具链不是一个软件，而是一条证据链。CubeMX 产生配置和初始化代码，编译器检查语法并生成目标文件，链接器形成固件，下载器把固件写入 Flash，调试器再通过 SWD 观察 CPU。分清阶段，才能知道错误发生在哪一层。

为什么这样做：先建立硬件和数据流模型，再记 HAL API，才能在 API 变化或板卡变化时仍然定位问题。

## STM32F103 / HAL 中的实现方式

- STM32F103 工程通常由启动文件、CMSIS、HAL 驱动、CubeMX 生成的 `Core` 文件和用户代码组成。
- `.uvprojx` 保存 MDK 工程组织，`.ioc` 保存 CubeMX 配置；`.axf` 带符号信息，`.hex/.bin` 用于烧录或发布。
- BOOT0 决定复位后的启动来源；正常运行和串口下载的状态必须分开确认。

## CubeMX 配置要点

1. 在 CubeMX 选择准确芯片或板卡型号。
2. `SYS -> Debug` 选择 Serial Wire，避免占用 SWD。
3. 配置 RCC/Clock、LED GPIO，Project Manager 选择 MDK-ARM。
4. 生成后打开 `.uvprojx`，先 Build，再配置 Debug Adapter 和 Flash Download。
5. 下载后复位运行，用断点确认进入 `main()`。

## 常用 HAL API

| API / 对象 | 作用 | 常见位置 |
|---|---|---|
| `HAL_Init` | 初始化 HAL 和默认 tick | main 开头 |
| `SystemClock_Config` | 配置系统/总线时钟 | HAL_Init 后 |
| `MX_GPIO_Init` | 使能 GPIO 时钟并初始化引脚 | 外设初始化阶段 |
| `HAL_GPIO_TogglePin` | 最小 LED 验证 | 主循环 |

## 最小实验 / 最小框架

> 代码性质：可直接移植的最小实验框架，变量名需按 CubeMX 实际生成结果调整。

```c
HAL_Init();
SystemClock_Config();
MX_GPIO_Init();

while (1)
{
    HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
    HAL_Delay(500);
}
```

## 调试方法

```text
确认板子供电和 GND
-> 确认工程芯片型号与实物一致
-> 确认 Pack、编译器和路径正常
-> 确认 DAP 被系统和 MDK 识别
-> 确认 SWDIO/SWCLK/NRST 接线
-> 确认 BOOT0 和复位状态
-> 断点验证是否进入 main
```

## 常见坑

| 现象 | 常见原因 | 处理方法 |
|---|---|---|
| 找不到芯片 | Device Pack 缺失或型号错误 | 安装对应 Pack 并重选器件 |
| DAP 不识别 | 驱动、USB 线或 Debug Adapter 选择错误 | 换数据线并检查 MDK Debug 设置 |
| 下载成功但不运行 | BOOT0、复位或代码卡死 | 恢复正常启动并断点检查 main |
| 重新生成丢代码 | 写在 USER CODE 外 | 业务代码移入 USER CODE 或 BSP |
| 编译路径异常 | 路径过深或含特殊字符 | 使用短、稳定的工程路径 |
