| WS2813E | 单线 RGB 灯珠/灯带类器件，按时序接收颜色数据 | `[38]` |

| ESP8266 | 常见 UART WiFi 模块，可用 AT 指令控制 | `[39-1]` 到 `[39-5]` |

| STA 模式 | ESP8266 作为站点连接路由器 | WiFi 配置 |
| AP 模式 | ESP8266 自己作为热点 | WiFi 配置 |
| 透传 | 串口数据直接透传到网络连接 | 数据发送 |
| 接收命令 | 网络侧发来的文本命令由 STM32 解析后控制外设 | LED / 蜂鸣器 / 舵机 |

### 常用 HAL API

| API / 宏 | 作用 | 常见用法 |
|----------|------|----------|
| `HAL_GPIO_WritePin()` | 控制普通 GPIO 电平 | 简单测试 RGB 数据脚、LED、蜂鸣器 |
| `HAL_TIM_PWM_Start()` | 启动 PWM 输出 | 舵机控制或定时驱动框架 |
| `HAL_UART_Transmit()` | 串口发送 AT 指令或调试文本 | ESP8266 指令发送 |
| `HAL_UART_Receive_IT()` | 中断接收串口数据 | ESP8266 基础接收 |
| `HAL_UARTEx_ReceiveToIdle_DMA()` | 空闲中断 + DMA 接收不定长数据 | ESP8266 响应和网络数据 |
| `__HAL_TIM_SET_COMPARE()` | 修改 PWM 占空比 | 舵机角度或其他输出控制 |

## 本质理解

WS2813E 的本质是：**STM32 不是发送普通串口数据，而是在一根数据线上输出严格宽度的高低电平，把颜色位流送进灯珠。**

```text
颜色数组
-> 按灯珠顺序展开成 bit
-> 按 0/1 编码成精确高低电平
-> 输出到 DATA
-> 保持低电平一段时间锁存
```

ESP8266 的本质是：**一个用 UART 控制的 WiFi 调制解调模块。STM32 不直接跑 TCP/IP 细节，而是通过 AT 指令让模块完成联网和收发。**

```text
STM32 UART
-> AT 指令
-> ESP8266
-> WiFi 网络
-> 服务器 / 手机 / 另一个客户端
```

PDF 可以支撑 USART 通信、GPIO 输出、PWM 舵机等基础能力，但当前 PDF 和已有笔记不足以支撑 WS2813E 的纳秒级时序和 ESP8266 的完整 AT 实验细节。所以这一章不写死固件版本、默认波特率、具体服务器地址或远程控制协议。

> 视频待核对：WS2813E 的具体时序窗口、颜色字节顺序、课程驱动方式、灯珠数量、数据引脚、供电方式；ESP8266 的 AT 固件版本、默认波特率、STA/AP/透传指令参数、服务器端配置和控制协议。

以实际开发板原理图和 CubeMX 配置为准。

## 工作流程 / 原理

### WS2813E 刷新流程

```text
准备每颗灯的颜色
-> 写入 RGB 缓冲区
-> 按课程确认的颜色顺序编码
-> 用 GPIO / TIM / DMA 输出严格时序
-> 输出 Reset / Latch 低电平
-> 灯珠更新颜色
```

单线 RGB 灯的关键不是 `HAL_GPIO_WritePin()` 会不会用，而是“时间是否足够准”。普通软件延时很容易被中断、编译优化、函数调用开销影响。

> 视频待核对：课程 `[38]` 使用纯 GPIO、定时器 PWM、DMA 还是其他方式生成 WS2813E 时序。

### ESP8266 基础 AT 测试

```text
串口参数确认
-> 发送 AT
-> 等待 OK
-> 查询版本或当前模式
-> 确认 STM32 与 ESP8266 串口收发正常
```

不要一开始就连 WiFi 或透传。先用最短的 AT 指令证明 UART 通了。

> 视频待核对：ESP8266 默认波特率、换行格式、复位等待时间和课程使用的串口工具测试步骤。

### STA 模式框架

```text
设置 STA 模式
-> 连接路由器
-> 查询 IP
-> 建立网络连接
-> 进入普通收发或透传
```

> 视频待核对：课程 `[39-2]` 的 STA 模式 AT 指令顺序、是否开启单连接/多连接、是否使用透传。

### AP 模式框架

```text
设置 AP 模式
-> 配置热点名称和密码
-> 手机连接热点
-> 建立连接
-> 进行串口和网络透传测试
```

> 视频待核对：课程 `[39-3]` 的 AP 模式热点配置、手机端工具、端口和数据收发方式。

### 发送传感器数据

```text
读取 DHT11 / 空气质量等数据
-> 格式化为文本或协议帧
-> 通过 ESP8266 发送
-> 网络端确认收到
```

发送格式可以是简单文本，也可以是自定义协议或 HTTP/MQTT 等，但当前资料不足以确定课程使用哪一种。

> 视频待核对：课程 `[39-4]` 的传感器数据格式、发送周期、网络协议和接收端工具。

### 接收命令控制外设

```text
ESP8266 收到网络数据
-> STM32 串口接收
-> 解析命令
-> 控制蜂鸣器 / LED / 舵机
-> 返回执行结果
```

这部分最容易把“通信层”和“业务层”混在一起。先把收到的原始字符串打印出来，再做命令解析。

> 视频待核对：课程 `[39-5]` 的命令格式、LED/蜂鸣器/舵机引脚、舵机 PWM 通道和反馈内容。

## CubeMX / MDK 配置

### WS2813E 配置思路

1. 选择当前 STM32F103 工程或新建工程。
2. 配置系统时钟，确保时序基准稳定。
3. 按课程确认的数据输出方式配置 GPIO 或 TIM。
4. 如果使用 GPIO 位带或直接寄存器方式，数据引脚配置为推挽输出。
5. 如果使用 TIM/PWM/DMA 方式，配置对应定时器通道和 DMA。
6. 基础调试阶段先点亮少量灯珠，减少供电和缓冲区变量。
7. 生成 MDK 工程。
8. 用户代码写在 `USER CODE` 区域；RGB 驱动建议放在 `BSP/ws2813e.c` 和 `BSP/ws2813e.h`。

WS2813E 数据引脚、灯珠数量、颜色顺序、时序参数、驱动方式：

### ESP8266 配置思路

1. 确认 ESP8266 模块供电能力，避免只看串口不看电源。
2. 在 CubeMX 中打开课程使用的 USART。
3. 配置 TX/RX 引脚，确认 STM32 TX 接 ESP8266 RX，STM32 RX 接 ESP8266 TX。
4. 配置波特率、数据位、停止位、校验位；具体以课程和模块固件为准。
5. 基础 AT 测试先用阻塞收发或中断接收。
6. 不定长响应和透传数据建议后续接入空闲中断 + DMA。
7. 如果要控制舵机，额外配置 TIM PWM；LED/蜂鸣器配置 GPIO 输出。
8. 生成 MDK 工程。
9. `BSP/esp8266.c` 只封装 AT 发送、等待响应、接收解析，不直接写复杂业务。

### `BSP/ws2813e.c`

```c
#include "ws2813e.h"

#define WS2813E_LED_COUNT  8

typedef struct
{
    uint8_t red;
    uint8_t green;
    uint8_t blue;
} WS2813E_Color;

static WS2813E_Color ws2813e_buf[WS2813E_LED_COUNT];

void WS2813E_SetPixel(uint16_t index, uint8_t red, uint8_t green, uint8_t blue)
{
    if (index >= WS2813E_LED_COUNT)
    {
        return;
    }

    ws2813e_buf[index].red = red;
    ws2813e_buf[index].green = green;
    ws2813e_buf[index].blue = blue;
}

void WS2813E_Clear(void)
{
    uint16_t i;

    for (i = 0; i < WS2813E_LED_COUNT; i++)
    {
        WS2813E_SetPixel(i, 0, 0, 0);
    }
}

void WS2813E_Refresh(void)
{
    /*
     * 这里不能用普通串口方式发送。
     * 需要按课程确认的 WS2813E 时序，把 ws2813e_buf 编码成单线波形。
     * 具体可由 GPIO 精确延时、TIM PWM、DMA 等方式实现。
     */
}
```

#include "esp8266.h"
#include "usart.h"
#include <string.h>

#define ESP8266_UART_HANDLE huart1

HAL_StatusTypeDef ESP8266_SendLine(const char *cmd)
{
    HAL_StatusTypeDef ret;

    ret = HAL_UART_Transmit(&ESP8266_UART_HANDLE,
                            (uint8_t *)cmd,
                            (uint16_t)strlen(cmd),
                            1000);
    if (ret != HAL_OK)
    {
        return ret;
    }

    return HAL_UART_Transmit(&ESP8266_UART_HANDLE, (uint8_t *)"\r\n", 2, 1000);
}

HAL_StatusTypeDef ESP8266_BasicTest(void)
{
    return ESP8266_SendLine("AT");
}

{

## 调试方法

### 供电

- WS2813E 灯珠电流可能远大于普通 LED，先确认电源能力。
- ESP8266 发射 WiFi 时电流会突然增大，供电不足会重启、乱码或无响应。
- 不确定模块电压等级时，不要直接接 5V。

### 共地

- STM32、WS2813E 外部电源、ESP8266、USB 串口工具必须共地。
- RGB 灯外部供电但没有共地时，数据线电平没有共同参考。
- ESP8266 串口转接工具和 STM32 共用时，也要确认地线连接。

### 接线

- WS2813E 的数据方向要接输入端，不要接到灯带输出端。
- ESP8266 的 TX/RX 要交叉连接。
- 如果模块有 EN、RST、BOOT 等控制脚，状态以实际模块资料为准。
- RGB 数据引脚、ESP8266 串口号、复位脚、舵机 PWM 通道：以实际开发板原理图和 CubeMX 配置为准。

### CubeMX 配置

- WS2813E 使用 GPIO、TIM、DMA 哪种方式，要和驱动代码一致。
- ESP8266 的 USART 参数必须和模块固件一致。
- 接收不定长数据时，确认中断或 DMA 已启动。
- 舵机控制命令如果涉及 PWM，先复用 `06_定时器PWM.md` 的检查方法。

### HAL API 返回值

- ESP8266 发送 AT 指令时先检查 `HAL_UART_Transmit()` 返回值。
- 使用中断接收时，确认 `HAL_UART_Receive_IT()` 或空闲 DMA 接收函数已启动。
- WS2813E 如果用 TIM/DMA，检查 `HAL_TIM_PWM_Start_DMA()` 或相关启动函数返回值。

### 逻辑分析仪 / 串口打印

- WS2813E 用逻辑分析仪看数据线高低电平宽度和 Reset 低电平。
- ESP8266 先用串口打印原始响应，不要直接进入命令解析。
- 透传阶段打印收发长度和原始字符串，避免把网络问题误判成业务问题。

### 外设协议

- WS2813E 的 0/1 编码、颜色顺序、Reset 时间必须按器件和课程确认。
- ESP8266 AT 指令通常要求特定换行、等待时间和响应判断。
- STA、AP、透传不是一个概念，先确认当前模块处在哪种模式。

### 业务逻辑

- RGB 颜色不对，先核对颜色顺序和缓冲区索引。
- ESP8266 能回 `OK` 但不能联网，优先看模式、SSID/密码、路由器频段和连接状态。
- 接收命令能打印但不能控制外设，再查命令解析、GPIO/PWM 输出和业务分支。

## 工程意义

WS2813E 代表“对时序要求很高的单线外设”。学会它以后，我会更重视 MCU 指令执行时间、中断影响、定时器/DMA 生成波形这些问题，而不是只依赖普通延时。

ESP8266 代表“用串口接入网络能力”的模块。真实项目里，STM32 常常不直接处理复杂网络协议，而是通过通信模块把传感器数据发出去，再把远程命令收回来控制本地执行器。

## 易混淆点

| 容易混淆 | 正确理解 |
|----------|----------|
| RGB 灯就是三个普通 PWM LED | WS2813E 是带控制芯片的单线串行 RGB 灯，重点是时序编码 |
| 颜色值写进数组就会显示 | 还必须调用刷新函数，把缓冲区按时序发出去 |
| 普通 `HAL_Delay()` 可以生成纳秒级时序 | 毫秒延时不适合生成 WS2813E 位时序 |
| ESP8266 是 STM32 的串口调试助手 | 它是 WiFi 模块，串口只是控制入口 |
| `AT` 返回 OK 就等于联网成功 | OK 只说明基础串口和 AT 解析正常 |
| STA、AP、透传是一回事 | STA 是连接路由器，AP 是自己开热点，透传是数据转发方式 |
| 接收控制命令必须一上来写完整协议 | 先打印原始数据，再做最小命令解析 |

## 我的理解

我现在把 WS2813E 理解成“一个特别挑时间的移位寄存器灯带”。它不是普通 LED，亮不亮很多时候不是颜色值错，而是供电、共地、数据方向或时序不对。

我现在把 ESP8266 理解成“串口后面接了一个 WiFi 世界”。STM32 先把 AT 指令发清楚，再等模块明确回复，最后才把传感器数据或控制命令放到网络收发里。

以后调 ESP8266，我会先只发 `AT` 看 `OK`，再查模式，再联网，再透传，最后才写业务协议。不要在串口还没稳定时就同时调 WiFi、服务器和 LED/舵机控制。
