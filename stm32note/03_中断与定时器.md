## 知识地图

| 新名词 | 解释 | 哪里出现 |
|--------|------|---------|
| 中断(Interrupt) | CPU 暂停当前任务，跳去执行一段紧急处理代码，处理完再回来 | [17] |
| NVIC | Nested Vectored Interrupt Controller，嵌套向量中断控制器。管理所有中断的使能、优先级、响应 | [17] |
| 中断向量表 | 一张表，地址 0x0000 0000 开始，每个表项存一个中断服务函数的入口地址 | [17] |
| ISR | Interrupt Service Routine，中断服务函数。中断发生时硬件自动跳转执行的函数 | [17] |
| 中断优先级 | 当多个中断同时发生时，优先级高的先被响应。Cortex-M3 支持抢占优先级和响应优先级两级 | [17] |
| 抢占优先级 | 高优先级中断可以打断正在执行的低优先级中断 | [17] |
| 响应优先级 | 同抢占优先级的中断同时来时，响应优先级高的排前面（但不打断对方） | [17] |
| TIM 溢出 | 定时器 CNT 计到 ARR 后归零，产生 Update Event（更新事件） | [17] |
| EXTI | External Interrupt，外部中断。引脚电平变化触发，不占用 CPU 轮询时间 | [18] |
| 边沿触发 | 只在电平翻转的瞬间触发中断（上升沿、下降沿、双边沿） | [18] |
| volatile | C 关键字，告诉编译器「这个变量可能被中断修改」，禁止优化掉重复读写 | [17] |

## 中断机制总览

### 中断的硬件流程

```
外设事件（如按键按下、定时器溢出）
    ↓ 硬件信号
NVIC（中断控制器）
    ↓ 检查：中断使能？优先级够高？
CPU
    ↓ 保存现场（自动压栈 R0-R3,R12,LR,PC,xPSR）
    ↓ 根据中断向量表跳转到 ISR
执行 ISR（用户代码）
    ↓ 返回
    ↓ 恢复现场（自动出栈）
继续执行被中断的代码
```

关键点：
- 保存现场和恢复现场是硬件自动完成的（Cortex-M3 特性），不需要写汇编
- 中断发生后 CPU 响应延迟固定为 12 个时钟周期（Cortex-M3 的确定性延迟）
- 中断里执行的函数叫 ISR 或回调函数（HAL 已经封装好）

### HAL 的中断封装方式

HAL 库把中断处理分了两层：

```
硬件中断 → stm32f1xx_it.c 中的 IRQHandler（HAL 生成）
                ↓ 清标志位等通用处理
           HAL 内部回调函数（如 HAL_TIM_PeriodElapsedCallback）
                ↓ __weak 声明，用户可以覆盖
           用户代码（自己写）
```

`__weak` 的含义：HAL 库定义了一个默认的空回调（什么都不做）。如果你在 main.c 里用相同函数名定义了同名函数，编译器会**覆盖**（override）弱定义，执行你的版本。这就是为什么不需要 include 任何额外头文件就能在 main.c 里写回调函数。

## [17] 系统定时器与中断闪灯

### HAL 定时器函数族速查

| 函数 | 作用 | 使用场景 |
|------|------|---------|
| `HAL_TIM_Base_Start(&htim)` | 启动定时器，**不产生**中断 | PWM 输出、TRGO 信号 |
| `HAL_TIM_Base_Start_IT(&htim)` | 启动定时器，**产生**溢出中断 | 定时回调 |
| `HAL_TIM_Base_Start_DMA(&htim, pData, Size)` | 启动定时器 + DMA | 高级应用 |
| `HAL_TIM_Base_Stop(&htim)` | 停止定时器 | 对应 Start |
| `HAL_TIM_Base_Stop_IT(&htim)` | 停止定时器中断 | 对应 Start_IT |
| `HAL_TIM_Base_Stop_DMA(&htim)` | 停止定时器 DMA | 对应 Start_DMA |
| `HAL_TIM_PeriodElapsedCallback(htim)` | 溢出回调（用户实现） | 定时到了做什么 |

> `_Start` vs `_Start_IT` 的区别：底层都是设置 TIM 的 CR1 寄存器，`_Start_IT` 额外设置了 DIER（DMA/Interrupt Enable Register）的 UIE（Update Interrupt Enable）位。只有该位置位，溢出事件才会触发中断。

### 定时器时钟来源——为什么 TIM2_CLK = 72MHz？

在 [01](01_准备与基础认知.md) 时钟树里提到过，这里详细展开其内部机制：

STM32F103 的时钟系统有这么一个特殊规则：**当 APBx 预分频器 ≠ 1 时，定时器时钟 = APBx 时钟 × 2。**

原因：这个 ×2 倍频是硬件设计上的补偿机制。APB 预分频降低了总线时钟，但为了不让总线上的定时器也跟着降速，硬件自动把定时器时钟翻倍。

```
APB1 预分频 = /2 → PCLK1 = 36MHz
  → TIM2/3/4 时钟 = 36MHz × 2 = 72MHz（不是因为定时器在 APB2 上）

APB2 预分频 = /1 → PCLK2 = 72MHz
  → TIM1/8 时钟 = 72MHz × 1 = 72MHz（分频 =1，不翻倍）
```

实际验证方法：在 `SystemClock_Config` 里查看 `APB1CLKDivider` 的值。如果是 `RCC_HCLK_DIV2`，则分频 ≠ 1，定时器时钟翻倍。

### 定时时间公式推导

```
输入：TIMx_CLK（定时器时钟频率，单位 Hz）
      PSC（预分频值，0~65535）
      ARR（自动重载值，0~65535）
      CNT（当前计数值，0~ARR，运行时变化）

步骤：
1. 预分频：  计数频率 = TIMx_CLK / (PSC + 1)
    （PSC=0 时不降频；PSC=7199 时降到 1/7200）

2. 计数周期：CNT 从 0 加到 ARR 需要 (ARR + 1) 次计数
    （ARR=0 时只计 1 次就溢出；ARR=9999 时计 10000 次）

3. 一次溢出时间：T = (PSC + 1) × (ARR + 1) / TIMx_CLK

示例：TIM2_CLK = 72MHz，要定时 1s
  选 PSC = 7199  → 计数频率 = 72M/7200 = 10kHz（100μs 一次）
  选 ARR = 9999  → 10000 次 × 100μs = 1s

验证：T = (7199+1) × (9999+1) / 72M = 7200 × 10000 / 72000000 = 1s
```

反算（已知时间求 PSC 和 ARR）：

```
给定 T 和 TIMx_CLK，求 PSC 和 ARR：

步骤：先选一个方便的计数频率，再算 ARR

例：T = 100ms, TIMx_CLK = 72MHz
  选 PSC = 7199 → 计数频率 = 10kHz（100μs 一次）
  ARR = T × 计数频率 - 1 = 0.1 × 10000 - 1 = 999

验证：(7199+1) × (999+1) / 72M = 7200 × 1000 / 72M = 0.1s ✓
```

### 中断优先级与 NVIC

Cortex-M3 的 NVIC 使用两级优先级：**抢占优先级（Preemption Priority）**和**响应优先级（Sub Priority）**。

抢占优先级决定「谁能打断谁」：
- 高抢占优先级的中断可以打断正在执行的低抢占优先级中断（嵌套）
- 同抢占优先级的中断不能互相打断

响应优先级决定「谁排前面」：
- 只有抢占优先级相同的中断同时到达时才有意义
- 响应优先级高的先被处理，但不会打断对方

优先级数字：0 = 最高优先级，15 = 最低优先级（数字和优先级方向相反）。

优先级分组：在 `HAL_Init()` 中设置，默认分 4 位抢占、0 位响应。需要响应优先级时可在 CubeMX → System Core → NVIC 里调整。

| 中断源 | 推荐抢占优先级 | 原因 |
|--------|-------------|------|
| SysTick | 15（最低） | 时基中断不能阻塞其他重要中断 |
| USART | 1 | 串口数据不及时取会丢 |
| TIM | 2 | 定时任务通常可以稍等 |
| EXTI（按键） | 3 | 按键响应慢几毫秒感觉不到 |

### HAL 定时器中断用法详解

```c
HAL_StatusTypeDef HAL_TIM_Base_Start_IT(TIM_HandleTypeDef *htim);
```

- 参数：`htim` —— 定时器句柄（CubeMX 生成的全局变量，如 `&htim2`）
- 返回值：`HAL_OK` 或 `HAL_ERROR`（通常在初始化阶段调用，检查返回值可辅助调试）
- 调用后，TIM 开始计数，每次溢出自动调用 `HAL_TIM_PeriodElapsedCallback`

```c
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM2)  // 区分是哪个定时器触发的
    {
        HAL_GPIO_TogglePin(GPIOB, GPIO_PIN_0);  // 你的操作
    }
}
```

- 参数 `htim->Instance` 是定时器硬件实例（如 `TIM2`、`TIM3`），类型是 `TIM_TypeDef*`
- 如果系统中用了多个定时器的中断，必须通过 `htim->Instance` 区分

### 中断回调里能做什么、不能做什么

中断回调运行在 ISR 上下文中。此时同优先级或更低优先级的中断被屏蔽。回调执行时间越长，系统对其他中断的响应越慢。

```c
// 中断里允许做的事（执行时间 < 几微秒）：
//   - 设置标志位（volatile 变量）
//   - 读写全局变量（原子操作）
//   - HAL_GPIO_TogglePin（极快，微秒级）

// 中断里绝对不能做的事：
HAL_Delay(100);      // 死锁！
                      // 原因：HAL_Delay 等 SysTick 中断来更新 uwTick
                      // 但 SysTick 优先级最低，当前 TIM 中断优先级更高
                      // → SysTick 永远进不来 → 永远等不到 → 卡死

printf("...");        // 阻塞太久！
                      // 原因：printf 通过串口发送，一次发多个字节
                      // 在 115200 波特下每个字符约 87μs, 一行字符串可能 >1ms

while (某条件);       // 可能永远不满足 → 卡死
```

正确做法：中断里只设标志位，真正处理放在 main 循环：

```c
volatile uint8_t timerFlag = 0;  // volatile 禁止编译器优化掉重复读

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM2)
        timerFlag = 1;  // 只设标志位，快速退出
}

// while(1) 中：
if (timerFlag)
{
    timerFlag = 0;
    // 在这里做耗时操作（printf、复杂运算等）
}
```

`volatile` 关键字的作用：编译器优化时可能会把「看似一样的读取」合并为一次。如果一个变量在中断里被修改了，而 main 循环没有写它，编译器可能会认为它不变并优化掉后续检查。volatile 强制每次读取都从内存取，避免此问题。

### CubeMX 配置

1. Timers → TIM2 → Clock Source: Internal Clock
2. Prescaler = 7199, Counter Period = 9999（1 秒）
3. NVIC → TIM2 global interrupt → Enable

### 易错点
- 中断回调不触发 → 用了 `_Start` 而非 `_Start_IT`
- 在中断里调 `HAL_Delay` → 程序卡死
- 标志位没用 `volatile` → main 循环读不到变化
- 定时时间差很多 → TIMx_CLK 算错了（APB1 ×2 规则）

## [18] 外部中断 EXTI

### EXTI 硬件机制

EXTI（External Interrupt/Event Controller）是独立于 GPIO 的中断控制器。每个 GPIO 引脚都可以通过 EXTI 产生中断。

```
GPIO 引脚电平变化
    ↓
边沿检测电路（上升沿/下降沿/双边沿）
    ↓
EXTI 线（EXTI0~EXTI15，共 16 条，分别对应 PAx/PBx/PCx...的同号引脚）
    ↓
NVIC → CPU 响应中断
```

关键硬件限制：**同一条 EXTI 线只能分配给一个端口的一个引脚。** 比如 PA0 用了 EXTI0，PB0 就不能同时用 EXTI0。这和 GPIO 的普通输入模式不同（普通模式没有这个限制）。

### HAL EXTI 函数速查

| 函数 | 作用 |
|------|------|
| `HAL_GPIO_EXTI_Callback(GPIO_Pin)` | EXTI 回调（用户实现），所有 EXTI 中断共用这一个回调 |
| `HAL_GPIO_EXTI_IRQHandler(GPIO_Pin)` | EXTI 中断处理函数（HAL 内部，`stm32f1xx_it.c` 调用） |

### 触发边沿

| 边沿 | 触发时刻 | 适用场景 |
|------|---------|---------|
| 下降沿 Falling | 电平从高变低的瞬间 | 按键按下（上拉输入）⭐ |
| 上升沿 Rising | 电平从低变高的瞬间 | 按键松开、某些传感器的上升信号 |
| 双边沿 Both | 任何一次变化都触发 | 需要检测变化次数 |

### CubeMX 配置

1. Pinout → 点目标引脚 → 选 GPIO_EXTIx（x 和引脚号对应）
2. System Core → GPIO → 该引脚 → GPIO Mode: External Interrupt Mode with Falling edge
3. NVIC → EXTI line interrupt → Enable

### 代码

```c
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_0)
    {
        // EXTI 里也需要消抖！机械按键抖动同样会产生多次边沿
        static uint32_t lastTime = 0;
        uint32_t now = HAL_GetTick();

        if (now - lastTime > 200)  // 200ms 内只响应一次
        {
            lastTime = now;
            HAL_GPIO_TogglePin(GPIOB, GPIO_PIN_0);
        }
    }
}
```

为什么能用 `HAL_GetTick()` 而不能用 `HAL_Delay()`？`HAL_GetTick()` 只是读一个全局变量，本身不阻塞，执行时间远小于 1μs。`HAL_Delay()` 内部有 while 循环等待，会卡住中断。

### 易错点
- EXTI 线共用限制：PA0 和 PB0 不能同时用 EXTI（都连 EXTI0）
- 按键在 EXTI 里同样要消抖（抖动边沿也会触发中断）
- 中断里不能调 `HAL_Delay`
