# 03 中断与定时器

> 覆盖课程：[17] [18]
>
> 目标：理解中断机制、SysTick、通用定时器中断、NVIC 优先级和 EXTI 外部中断。

## 概念

### 知识地图

| 名词 | 工程含义 | 常见位置 |
|------|----------|----------|
| 中断 | CPU 暂停当前代码，先去处理紧急事件，处理完再回来 | [17] |
| NVIC | Nested Vectored Interrupt Controller，嵌套向量中断控制器 | [17] |
| 中断向量表 | 保存各个中断服务函数入口地址的表 | [17] |
| ISR | Interrupt Service Routine，中断服务函数 | [17] |
| 抢占优先级 | 决定一个中断能不能打断另一个中断 | [17] |
| 响应优先级 | 同抢占优先级下，多个中断同时到达时谁先排队 | [17] |
| TIM 溢出 | 定时器 `CNT` 计到 `ARR` 后回到 0，并产生 Update Event | [17] |
| EXTI | External Interrupt，外部中断，由 GPIO 边沿触发 | [18] |
| 边沿触发 | 只在电平变化瞬间触发：上升沿、下降沿或双边沿 | [18] |
| `volatile` | 告诉编译器变量可能被中断/硬件修改，禁止错误优化 | [17] |

### 中断相关 HAL API

| API | 作用 |
|-----|------|
| `HAL_TIM_Base_Start(&htim)` | 启动定时器，不开启溢出中断 |
| `HAL_TIM_Base_Start_IT(&htim)` | 启动定时器，并开启溢出中断 |
| `HAL_TIM_Base_Stop_IT(&htim)` | 停止定时器中断 |
| `HAL_TIM_PeriodElapsedCallback(htim)` | 定时器溢出回调，用户实现 |
| `HAL_GPIO_EXTI_IRQHandler(Pin)` | HAL EXTI 中断处理入口 |
| `HAL_GPIO_EXTI_Callback(Pin)` | EXTI 用户回调 |
| `HAL_GetTick()` | 读取 HAL 毫秒时基 |

## 本质理解

中断的本质是：**硬件事件主动通知 CPU**。这样 CPU 不需要一直轮询等待。

```text
轮询方式：
while (1) 一直检查按键/定时器/串口状态

中断方式：
事件发生 -> 硬件通知 NVIC -> CPU 自动跳到 ISR -> 回来继续执行主循环
```

定时器中断解决的是“多久做一次”的问题；EXTI 解决的是“外部引脚变化时立刻响应”的问题。

## 工作流程 / 原理

### 中断硬件流程

```text
外设事件（按键边沿、定时器溢出、串口接收）
    -> NVIC 检查中断是否使能、优先级是否允许
    -> CPU 自动保存现场（压栈 R0-R3、R12、LR、PC、xPSR）
    -> 查中断向量表
    -> 跳转到 ISR
    -> 执行中断处理代码
    -> 自动恢复现场
    -> 回到被打断的位置继续运行
```

保存和恢复现场由 Cortex-M3 硬件完成，普通 HAL 工程里不需要手写汇编。

### HAL 的中断封装方式

HAL 把中断拆成两层：

```text
硬件中断
-> stm32f1xx_it.c 中的 XXX_IRQHandler()
-> HAL_xxx_IRQHandler()
-> HAL 内部清标志、更新状态
-> 调用 __weak 回调函数
-> 用户在 main.c 中实现同名回调
```

`__weak` 表示弱定义。HAL 提供一个空的默认回调；用户写同名函数后，链接时会使用用户版本。

### `_Start` 和 `_Start_IT` 的区别

| 函数 | 是否计数 | 是否进中断 | 适用场景 |
|------|----------|------------|----------|
| `HAL_TIM_Base_Start()` | 是 | 否 | PWM、TRGO、只需要定时器硬件运行 |
| `HAL_TIM_Base_Start_IT()` | 是 | 是 | 周期性执行用户代码 |

`_Start_IT` 会额外打开定时器的 Update Interrupt Enable 位。只调用 `_Start()` 时，定时器会运行，但溢出不会进入回调。

### 定时器时钟

STM32F103 常见时钟配置：

```text
SYSCLK = 72 MHz
HCLK   = 72 MHz
PCLK1  = 36 MHz
PCLK2  = 72 MHz
```

关键规则：

**当 APBx 预分频不等于 1 时，该总线上的定时器时钟 = PCLKx x 2。**

```text
APB1 Prescaler = /2
PCLK1 = 36 MHz
TIM2/3/4_CLK = 36 MHz x 2 = 72 MHz
```

注意：TIM2/3/4 仍然挂在 APB1 上，不是因为它们跑到 APB2 上才有 72 MHz。

### 定时时间公式

```text
计数频率 = TIMx_CLK / (PSC + 1)
溢出次数 = ARR + 1
溢出周期 = (PSC + 1) x (ARR + 1) / TIMx_CLK
```

例：TIM2_CLK = 72 MHz，要 1 s 溢出一次：

```text
PSC = 7199
ARR = 9999

计数频率 = 72 MHz / 7200 = 10 kHz
计数周期 = 0.1 ms
溢出时间 = 10000 x 0.1 ms = 1 s
```

反算方法：先选一个方便的计数频率，再算 ARR。

```text
目标 T = 100 ms
TIMx_CLK = 72 MHz

选 PSC = 7199 -> 计数频率 = 10 kHz
ARR = T x 计数频率 - 1
    = 0.1 x 10000 - 1
    = 999
```

### NVIC 优先级

Cortex-M3 使用两级优先级：

| 优先级 | 作用 |
|--------|------|
| 抢占优先级 | 高抢占优先级可打断低抢占优先级 |
| 响应优先级 | 抢占优先级相同时，决定同时到达的排队顺序 |

数字越小，优先级越高。例如 0 最高，15 最低。

工程建议：

| 中断源 | 建议 | 原因 |
|--------|------|------|
| SysTick | 保持较低优先级 | 只负责 HAL 时基 |
| USART | 较高 | 数据不及时取可能丢 |
| TIM | 中等 | 周期任务一般可接受少量延迟 |
| EXTI 按键 | 较低 | 人手动作很慢，毫秒级延迟无感 |

### 中断回调里能做什么

中断回调要短、快、可预测。

允许做：

- 设置 `volatile` 标志位。
- 读取简单状态。
- 翻转 GPIO。
- 记录时间戳。

避免做：

- `HAL_Delay()`。
- 长时间 `printf()`。
- 等待某个条件的 `while`。
- 大量浮点运算。
- 复杂协议解析。

典型错误：

```c
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    HAL_Delay(100);  // 错误：中断里阻塞等待，可能卡死
}
```

正确思路：中断里设标志，主循环里处理。

```c
volatile uint8_t timerFlag = 0;

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM2)
    {
        timerFlag = 1;
    }
}

while (1)
{
    if (timerFlag)
    {
        timerFlag = 0;
        HAL_GPIO_TogglePin(GPIOB, GPIO_PIN_0);
    }
}
```

`volatile` 的意义：变量在中断中被修改，主循环中读取。没有 `volatile` 时，编译器可能把主循环里的重复读取优化掉。

### EXTI 硬件机制

```text
GPIO 引脚电平变化
-> 边沿检测电路
-> EXTI0~EXTI15
-> NVIC
-> CPU 响应中断
-> HAL_GPIO_EXTI_Callback()
```

关键限制：

**同一条 EXTI 线只能连接一个端口的同号引脚。**

例如：

- `PA0` 使用 `EXTI0`。
- `PB0` 也要使用 `EXTI0`。
- 两者不能同时作为 EXTI 使用。

普通 GPIO 输入没有这个限制，只有 EXTI 有这个限制。

### EXTI 触发边沿

| 边沿 | 触发时刻 | 典型场景 |
|------|----------|----------|
| Falling | 高 -> 低 | 上拉按键按下 |
| Rising | 低 -> 高 | 按键松开，部分传感器触发 |
| Both | 任意变化 | 需要统计变化次数 |

## CubeMX 配置

### TIM2 1 秒定时中断

1. `Timers -> TIM2`。
2. `Clock Source` 选择 `Internal Clock`。
3. `Prescaler` = `7199`。
4. `Counter Period` = `9999`。
5. `NVIC Settings` 中勾选 `TIM2 global interrupt`。
6. 在 `main()` 初始化后调用：

```c
HAL_TIM_Base_Start_IT(&htim2);
```

### EXTI 按键中断

1. `Pinout` 点击目标引脚，例如 `PA0`。
2. 选择 `GPIO_EXTI0`。
3. `System Core -> GPIO` 设置：
   - `GPIO mode`：`External Interrupt Mode with Falling edge trigger detection`
   - `GPIO Pull-up/Pull-down`：`Pull-up`
4. `NVIC Settings` 勾选对应 EXTI line interrupt。

## HAL 函数 / API

### `HAL_TIM_Base_Start_IT`

```c
HAL_StatusTypeDef HAL_TIM_Base_Start_IT(TIM_HandleTypeDef *htim);
```

参数：`htim` 是 CubeMX 生成的定时器句柄，例如 `&htim2`。

作用：启动定时器计数，并允许溢出中断触发。

### `HAL_TIM_PeriodElapsedCallback`

```c
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM2)
    {
        // TIM2 溢出事件
    }
}
```

如果多个定时器都开启中断，必须用 `htim->Instance` 区分来源。

### `HAL_GPIO_EXTI_Callback`

```c
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_0)
    {
        // EXTI0 触发
    }
}
```

所有 GPIO EXTI 共用这一个回调，用 `GPIO_Pin` 区分是哪一条线。

## 示例代码

### TIM2 中断闪灯

```c
/* USER CODE BEGIN 2 */
HAL_TIM_Base_Start_IT(&htim2);
/* USER CODE END 2 */

/* USER CODE BEGIN 4 */
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM2)
    {
        HAL_GPIO_TogglePin(GPIOB, GPIO_PIN_0);
    }
}
/* USER CODE END 4 */
```

### TIM2 中断只设标志位

```c
/* USER CODE BEGIN PV */
volatile uint8_t timerFlag = 0;
/* USER CODE END PV */

/* USER CODE BEGIN 2 */
HAL_TIM_Base_Start_IT(&htim2);
/* USER CODE END 2 */

while (1)
{
    if (timerFlag)
    {
        timerFlag = 0;
        printf("1 second passed\r\n");
    }
}

/* USER CODE BEGIN 4 */
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM2)
    {
        timerFlag = 1;
    }
}
/* USER CODE END 4 */
```

### EXTI 按键中断消抖

```c
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_0)
    {
        static uint32_t lastTime = 0;
        uint32_t now = HAL_GetTick();

        if (now - lastTime > 200)
        {
            lastTime = now;
            HAL_GPIO_TogglePin(GPIOB, GPIO_PIN_0);
        }
    }
}
```

`HAL_GetTick()` 只是读取毫秒计数，不阻塞；`HAL_Delay()` 会等待时间流逝，不能放在中断里。

## 常见错误

| 问题 | 常见原因 | 解决方法 |
|------|----------|----------|
| 定时器回调不触发 | 调了 `_Start()` 而不是 `_Start_IT()` | 改为 `HAL_TIM_Base_Start_IT()` |
| 中断函数进不去 | CubeMX 没勾 NVIC | 打开对应中断使能 |
| 程序卡死在中断里 | 中断中调用 `HAL_Delay()` 或长时间阻塞 | 中断只设标志位，主循环处理 |
| 主循环读不到标志位变化 | 变量未加 `volatile` | 中断和主循环共享变量加 `volatile` |
| 定时时间不准 | TIMx_CLK 计算错误 | 检查 APB 分频和定时器 x2 规则 |
| EXTI 不触发 | 边沿选错或 Pull 配置错误 | 上拉按键按下通常选 Falling |
| PA0 和 PB0 都想做 EXTI | 同一 EXTI 线冲突 | 换不同编号的引脚 |
| 按键中断触发多次 | 机械抖动 | 用时间戳消抖或主循环状态机 |

## 调试方法

### 定时器中断调试

1. 确认 `MX_TIMx_Init()` 被调用。
2. 确认 `HAL_TIM_Base_Start_IT(&htimx)` 被调用且返回 `HAL_OK`。
3. 在 `TIMx_IRQHandler()` 打断点，确认硬件中断是否进入。
4. 在 `HAL_TIM_PeriodElapsedCallback()` 打断点，确认 HAL 回调是否进入。
5. 检查 `htim->Instance` 判断是否写错。

### EXTI 调试

1. 用万用表确认按键电平确实变化。
2. 检查 CubeMX 是否配置为 `GPIO_EXTIx`。
3. 检查 NVIC 是否启用对应 EXTI line。
4. 在 `EXTIx_IRQHandler()` 打断点。
5. 再在 `HAL_GPIO_EXTI_Callback()` 打断点。

## 工程意义

中断让工程从“CPU 一直等”变成“事件来了再处理”。这是单片机从玩具程序走向工程程序的关键一步。

定时器中断适合：

- 周期性任务调度。
- 传感器定时读取。
- 软件计时。
- 非阻塞状态机节拍。

EXTI 适合：

- 按键。
- 外部模块的数据就绪引脚。
- 编码器边沿。
- 低功耗唤醒。

工程上要养成一个习惯：**中断只做通知，不做重活。**

## 易混淆点

| 容易混淆 | 正确理解 |
|----------|----------|
| `_Start` 和 `_Start_IT` | `_Start` 只启动硬件，`_Start_IT` 还允许中断 |
| ISR 和 Callback | ISR 是真正中断入口，Callback 是 HAL 调给用户的钩子 |
| 抢占优先级和响应优先级 | 抢占决定能否打断，响应决定同级排队 |
| SysTick 和 TIM2 | SysTick 是内核定时器，TIM2 是 STM32 外设定时器 |
| `HAL_GetTick()` 和 `HAL_Delay()` | 前者读时间，后者阻塞等待 |
| EXTI 和 GPIO 输入 | EXTI 是边沿中断，普通 GPIO 输入是读取当前电平 |
| TIM2_CLK 和 PCLK1 | APB1 分频不为 1 时，TIM2_CLK = PCLK1 x 2 |

## 我的理解

中断不是“代码突然乱跳”，而是硬件帮我把事件送到固定入口。

我现在的理解是：

- 定时器负责给系统提供可靠节拍。
- EXTI 负责让外部事件不用轮询也能被发现。
- NVIC 是所有中断的调度中心。
- HAL 回调是我写业务逻辑的入口。
- 中断里越短越好，复杂工作应该回到 `while (1)`。

以后看到一个中断问题，我先按这条链路查：

```text
外设事件有没有发生
-> 中断源有没有使能
-> NVIC 有没有使能
-> IRQHandler 有没有进
-> HAL Callback 有没有进
-> 用户判断条件有没有写错
```
