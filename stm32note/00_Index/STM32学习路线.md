# STM32 学习路线

> 学习原则：每一阶段都要完成“能解释、能配置、能写最小代码、能排错”四个闭环。只看完正文不算完成。

## 第一阶段：跑通工具链

- 学什么：[[工具链与开发环境]]，理解 CubeMX、MDK、Pack、HAL、SWD 和串口下载的分工。
- 为什么：后续所有问题都建立在工程能正确生成、编译、下载和调试之上。
- 最小验收：新建工程，下载 LED 闪烁程序，能区分编译、链接、下载和运行失败。
- 常见坑：芯片包缺失、下载器未识别、BOOT0 状态错误、工程路径或芯片型号不匹配。

## 第二阶段：理解启动与时钟

- 学什么：[[STM32体系结构与启动流程]]、[[RCC时钟树]]。
- 为什么：外设寄存器、向量表和实际时钟决定 HAL 代码为何有效。
- 最小验收：能画出“复位到 `while (1)`”流程，并从 Clock Configuration 推导 HCLK、PCLK 和 TIM 时钟。
- 常见坑：把 `HAL_Init()` 当成所有外设初始化、忽略 APB 分频后的定时器倍频。

## 第三阶段：掌握 GPIO 与外部事件

- 学什么：[[GPIO与AFIO]]、[[NVIC_EXTI_SysTick]]、[[数字传感器与LM393]]、[[蜂鸣器与简单执行器]]。
- 为什么：输入、输出、复用和中断是板级控制的最小积木。
- 最小验收：完成 LED、按键轮询、按键 EXTI 和数字传感器触发蜂鸣器。
- 常见坑：有效电平判断反、输入悬空、EXTI 端口映射错误、中断回调中阻塞。

## 第四阶段：建立时间基准

- 学什么：[[TIM定时器体系]]、[[DWT与调试计时]]。
- 为什么：定时、测量和严格时序都需要先知道计数频率与误差来源。
- 最小验收：用 TIM 周期中断翻转 GPIO，用 DWT 测量一个函数的周期数。
- 常见坑：PSC/ARR 少减 1、TIM 时钟算错、把 DWT 忙等用于长延时。

## 第五阶段：输出 PWM

- 学什么：[[TIM_PWM输出]]、[[电机控制_TB6612FNG]]。
- 为什么：PWM 是亮度、舵机和电机调速的共同控制量。
- 最小验收：测得目标频率和占空比的 PWM，再通过独立供电安全驱动一个执行器。
- 常见坑：通道或复用引脚选错、忘记启动 PWM、负载供电不足、功率地未共地。

## 第六阶段：测量外部信号

- 学什么：[[TIM输入捕获与编码器]]。
- 为什么：输入捕获把外部边沿时间交给硬件记录，编码器模式把 A/B 相直接变成计数方向。
- 最小验收：读取编码器 CNT，或测量一个已知 PWM 的频率和脉宽。
- 常见坑：计数频率未知、边沿配置错误、未处理溢出、把 CCR 与 CNT 混淆。

## 第七阶段：建立模拟采样链

- 学什么：[[ADC与模拟采样]]、[[DMA与缓冲区]]、[[TIM触发ADC]]。
- 为什么：可靠采样不仅是读一个数，还包括触发节拍、通道顺序、缓冲区和换算。
- 最小验收：先轮询单通道，再用 DMA 连续采样，最后由 TIM 固定节拍触发 ADC。
- 常见坑：GPIO 未设 Analog、Rank 与数组下标错、DMA 长度错、参考电压假设错误。

## 第八阶段：掌握三类基础通信

- 学什么：[[USART与串口协议]]、[[I2C总线]]、[[SPI总线与Flash]]。
- 为什么：USART 解决异步字节流，I2C 解决共享寄存器总线，SPI 解决高速同步传输。
- 最小验收：串口收发一帧数据、I2C 读设备 ID、SPI 读 Flash ID 并检查 HAL 返回值。
- 常见坑：串口帧格式不一致、I2C 地址移位混乱、SPI 模式或片选时序错误。

## 第九阶段：完成模块 bring-up

- 学什么：[[DHT11单总线温湿度]]、[[OLED显示模块]]、[[MPU6050姿态传感器]]、[[MAX30102心率血氧]]、[[VL53L0X激光测距]]、[[BMP280_SPL06气压计]]、[[WS2813E_RGB灯]]、[[ESP8266_AT指令]]。
- 为什么：复杂模块应拆成“物理连接、总线通信、ID/状态、原始数据、换算/算法、显示”逐层验证。
- 最小验收：每个模块至少拿到一个可解释的 ID、状态或原始数据证据。
- 常见坑：直接移植整套库、忽略供电和上拉、把算法无输出误判为总线故障。

模块参数先查 [[视频实测核对表]]。地址、寄存器、时序和算法没有手册或实测证据时，只保留框架。

## 第十阶段：工程化与系统集成

- 学什么：[[BSP工程模板与代码组织]]、[[HAL_API速查表]]、[[通用调试方法]]、[[传感器采集与显示]]、[[串口协议解析]]、[[联网控制与总线通信]]。
- 为什么：真实项目的问题多发生在模块边界、缓冲区生命周期、状态机和故障恢复，而不是单个 HAL API。
- 最小验收：BSP 与业务代码分层；串口可处理半包/粘包；通信断开后能超时并恢复；调试过程有可复现证据。
- 常见坑：在回调中做重业务、长期 DMA 使用局部数组、协议无长度/校验、网络状态机没有超时。
