# 17-18 定时器与中断

> 本章是 STM32 最核心的外设之一。定时器是所有「定时执行」、「时间测量」、「波形生成」的基础。

---

## 定时器家族速览

| 类型 | 型号 | 位数 | 主要功能 |
|------|------|------|---------|
| 基本定时器 | TIM6/7 | 16位 | 只有定时功能，无输入输出通道 |
| 通用定时器 | TIM2/3/4/5 | 16位 | 定时 + PWM + 输入捕获 + 输出比较 |
| 高级定时器 | TIM1/8 | 16位 | 通用功能 + 互补输出 + 死区 + 刹车（电机专用） |

> 本笔记以 **TIM2（通用定时器）** 为例。

---

## ⭐ 先确认定时器时钟

这是新手算错定时时间的头号原因。

**规则**：如果定时器所在 APB 总线的分频系数 **≠ 1**，则定时器时钟自动 **× 2**。

| 定时器 | 所在总线 | 总线频率 | 分频系数 | 定时器实际时钟 |
|--------|---------|---------|---------|-------------|
| TIM1 | APB2 | 72MHz | /1 | 72MHz |
| TIM2/3/4 | APB1 | 36MHz | /2（≠1 → ×2） | **72MHz** |
| TIM6/7 | APB1 | 36MHz | /2（≠1 → ×2） | **72MHz** |

> 💡 在 CubeMX 的 Clock Configuration 里可以看到每个定时器的实际时钟频率，配置前先确认。

## 定时器工作原理

```
TIMx_CLK（定时器时钟源）
    ↓ ÷ (PSC + 1)       ← 预分频器：降速，每 (PSC+1) 个时钟触发一次计数
计数时钟
    ↓ 每个时钟 CNT + 1
CNT 计数器（当前计数值）
    ↓ CNT == ARR 时溢出 → 产生更新事件/中断
ARR 自动重载值（计数上限）
    └→ CNT 自动归零，重新开始计数
```

### 定时时间公式 ⭐

```
T = (PSC + 1) × (ARR + 1) / TIMx_CLK

例：TIM2_CLK = 72MHz，想要定时 1 秒
PSC = 7199（分频后 = 72M / 7200 = 10kHz）
ARR = 9999（10000 次计数 = 1 秒）
T = 7200 × 10000 / 72,000,000 = 1s ✓

验证：72MHz / 7200 = 10kHz  →  10kHz / 10000 = 1Hz = 1s
```

### 快速定值思路

| 你想要的 | 选择策略 |
|---------|---------|
| 1ms 定时 | PSC=71, ARR=999 → 72M/72/1000 = 1kHz = 1ms |
| 1s 定时 | PSC=7199, ARR=9999 → 72M/7200/10000 = 1Hz = 1s |
| 任意 T | 先定 ARR=999（方便算占空比），再算 PSC = 72M×T/1000 - 1 |

## CubeMX 配置步骤

1. **Timers** → **TIM2** → Clock Source: **Internal Clock**
2. Prescaler = 7199，Counter Period = 9999（即 ARR）
3. **NVIC Settings** 标签 → TIM2 global interrupt → **Enable**
4. 生成代码

## HAL 定时器启动函数——两个版本别搞混

```c
// 在 main() 的 while(1) 之前调用

// 版本1：只启动定时器，不产生中断
HAL_TIM_Base_Start(&htim2);

// 版本2：启动定时器 + 使能中断（需要中断回调时用这个）⭐
HAL_TIM_Base_Start_IT(&htim2);
```

> 🔴 **新手高频踩坑**：写了 `HAL_TIM_PeriodElapsedCallback` 回调，但启动时调的是 `_Start` 而不是 `_Start_IT` → 回调永远不会触发。

## 中断回调函数

```c
// 放在 main.c 的 /* USER CODE BEGIN 4 */ 区域
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM2)
    {
        HAL_GPIO_TogglePin(GPIOB, GPIO_PIN_0);  // 每 1 秒翻转 LED
    }
}
```

### 🔴 中断里绝对不能做的事

```c
// ❌ 绝对禁止
HAL_Delay(100);              // 死等 → SysTick 优先级低 → 死锁！
printf("in ISR\r\n");        // 阻塞打印 → 太慢 → 中断堆积

// ✅ 应该这样做
// 1. 设个标志位，在 main 循环里处理
// 2. 用 HAL_GetTick() 做时间判断（不阻塞）
volatile uint8_t flag = 0;   // volatile 很重要！告诉编译器这个变量会被中断修改

// 中断里：
flag = 1;

// main 循环里：
if (flag) {
    // 做耗时的事
    flag = 0;
}
```

> **为什么 `HAL_Delay()` 会在中断里死锁？** 因为它依赖 SysTick 中断来计数，而 SysTick 的优先级最低（15）。如果你的中断优先级高于 SysTick，SysTick 永远进不来 → `HAL_Delay` 永远等不到 → 程序卡死。

---

## 中断优先级（NVIC）

```
优先级数字越小 = 优先级越高

抢占优先级（Preemption Priority）：
  → 高抢占优先级可以打断低抢占优先级的中断

响应优先级（Sub Priority）：
  → 同抢占优先级时，决定谁先执行（不可互相打断）
```

### 常用优先级分配

| 中断源 | 抢占优先级 | 说明 |
|--------|----------|------|
| SysTick | 15（最低） | HAL 时基，优先级最低是**故意**的——不能让它打断重要中断 |
| UART | 1 | 串口数据不能丢 |
| TIM | 2 | 定时触发 |
| EXTI（按键） | 3 | 按键响应可以慢一点 |

## 外部中断 EXTI（[18]）

GPIO 引脚可以配置为外部中断——引脚电平变化时自动进中断处理。

### 触发方式

| 方式 | 场景 |
|------|------|
| 下降沿（Falling） | 按键按下时触发 ⭐ 最常用 |
| 上升沿（Rising） | 按键松开时触发 |
| 双边沿（Both） | 任意电平变化都触发 |

### 中断里也要消抖

```c
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_0)
    {
        static uint32_t lastTime = 0;
        if (HAL_GetTick() - lastTime > 200)  // 200ms 防抖
        {
            lastTime = HAL_GetTick();
            HAL_GPIO_TogglePin(GPIOB, GPIO_PIN_0);
            // 注意：这里用的 HAL_GetTick()，不是 HAL_Delay()
        }
    }
}
```

## 踩坑记录

- [ ] 定时器时间不对 → 检查 TIMx_CLK 是不是你想的那个值（APB1 的 ×2 规则）
- [ ] 中断回调不触发 → `HAL_TIM_Base_Start` 忘了加 `_IT`
- [ ] 程序一进中断就卡死 → 中断里调了 `HAL_Delay()`
- [ ] EXTI 触发一次后不再触发 → 没清中断标志（HAL 库的回调里已经帮你清了，但如果你自己写中断服务函数要注意）
- [ ] 标志位没用 `volatile` → 编译器优化导致 main 循环读不到变化
