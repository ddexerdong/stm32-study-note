# MPU6050 姿态传感器

> 模块定位：用 I2C 寄存器读写完成六轴传感器基础 bring-up。
>
> 原始来源：[[12_I2C传感器]]。
---
## 本节目标

- 能完成设备识别、唤醒、量程配置和原始六轴读取。
- 能正确拼接多字节原始值，并把换算参数与手册版本绑定。
- 能区分原始传感器数据和姿态融合结果。

## 核心概念

### 知识地图

| 名词 | 工程含义 |
|---|---|
| 加速度计 | 测量比力/重力方向 |
| 陀螺仪 | 测量角速度 |
| WHO_AM_I | 设备身份寄存器 |
| 睡眠位 | 上电后需解除低功耗状态 |
| 量程比例 | 原始 LSB 到工程单位的换算依据 |

### 模块作用

读取三轴加速度、三轴角速度和温度原始数据，建立 IMU 寄存器驱动与换算流程。

### 基础主线

```text
地址 ACK
-> 读 WHO_AM_I
-> 解除睡眠
-> 配置加速度/陀螺仪量程
-> 连续读取原始数据
-> 按量程换算
-> 串口或 OLED 显示
```

### 边界

基础实验只要求原始加速度、角速度和温度数据可信。姿态角通常还涉及滤波、融合或 DMP，不能把“读寄存器”直接等同于“得到姿态”。

> 视频待核对：模块地址、WHO_AM_I、寄存器宏、量程、换算比例、连续读取封装和课程是否涉及姿态融合。

## 本质理解

MPU6050 直接给出的是加速度计和陀螺仪原始值，不是最终姿态角。字节拼接、符号扩展、量程比例和偏置校准正确后，姿态才由后续融合算法得到。

## 硬件连接关系

- I2C SCL/SDA 和共地
- 模块地址脚状态决定地址，需实测/查原理图
- 中断脚可选，基础读取不依赖
- 模块电平和上拉需兼容

## 通信 / 控制链路

```text
扫描地址
-> 读 WHO_AM_I
-> 解除睡眠
-> 配置量程/滤波
-> 连续读取 14 字节类原始块
-> 拼接 int16
-> 按量程换算
-> 静态姿态校验
```

## CubeMX 配置要点

1. 启用 I2C
2. 先阻塞 API 读 WHO_AM_I
3. 串口打印原始数据
4. 需要数据中断时再配置 EXTI

## 本模块依赖的 HAL 层

| 模块动作 | 依赖 HAL | 说明 |
|---|---|---|
| 探测 I2C 地址 | `HAL_I2C_IsDeviceReady()` | 确认 ACK；地址表达方式按 HAL 和驱动宏统一 |
| 读取 WHO_AM_I/状态/连续原始值 | `HAL_I2C_Mem_Read()` | 明确寄存器地址宽度、读取长度和多字节顺序 |
| 解除睡眠、配置量程/滤波 | `HAL_I2C_Mem_Write()` | 每次写入检查 `HAL_OK`，必要时读回确认 |
| 数据就绪中断 | `HAL_GPIO_EXTI_Callback()` | 可选；只发布“数据可读”事件，不在回调中做完整 I2C 读取和姿态计算 |
| 打印原始六轴值 | `HAL_UART_Transmit()` 或 `printf` | 用于先证明原始数据变化，再接换算/融合 |

HAL 只负责 I2C 和可选 EXTI。寄存器值、量程比例、温度公式和姿态融合算法属于 MPU6050 手册/算法层，不能由 HAL API 推导。

### 典型调用顺序

```text
MX_I2Cx_Init()
-> HAL_I2C_IsDeviceReady()
-> HAL_I2C_Mem_Read() 核对 WHO_AM_I
-> HAL_I2C_Mem_Write() 解除睡眠并写最少配置
-> 连续 HAL_I2C_Mem_Read() 读取原始字节
-> 拼接有符号值
-> 按已核对量程换算并输出
```

### 什么时候用哪个函数？

| 场景 | 推荐函数 |
|---|---|
| 地址 bring-up | `HAL_I2C_IsDeviceReady()` |
| 读 ID/原始寄存器 | `HAL_I2C_Mem_Read()` |
| 写工作模式/量程 | `HAL_I2C_Mem_Write()` |
| 按数据就绪事件采样 | EXTI 回调置标志，主循环执行 I2C 读取 |

## Bring-up 顺序

1. 确认供电、电平、I2C 上拉和地址脚状态。
2. 读取 `WHO_AM_I`，证明地址和寄存器访问正确。
3. 解除睡眠，再读取连续六轴原始字节。
4. 验证高低字节拼接、符号和静止时的轴向变化。
5. 按已确认量程换算并处理偏置。
6. 最后再加入滤波、姿态融合和显示。

## 最小驱动框架

> 代码性质：示例框架，用于理解调用顺序，不能保证直接编译。

```c
static uint8_t MPU6050_ReadWhoAmI(uint8_t *id)
{
    return HAL_I2C_Mem_Read(&hi2c1, MPU6050_ADDR_HAL,
                             MPU6050_REG_WHO_AM_I, MPU6050_REG_ADDR_SIZE,
                             id, 1U, MPU6050_I2C_TIMEOUT_MS) == HAL_OK;
}

static uint8_t MPU6050_Wake(void)
{
    uint8_t value = MPU6050_PWR_MGMT_1_WAKE_VALUE;
    return HAL_I2C_Mem_Write(&hi2c1, MPU6050_ADDR_HAL,
                              MPU6050_REG_PWR_MGMT_1, MPU6050_REG_ADDR_SIZE,
                              &value, 1U, MPU6050_I2C_TIMEOUT_MS) == HAL_OK;
}

static int16_t MPU6050_JoinSigned(uint8_t high, uint8_t low)
{
    return (int16_t)(((uint16_t)high << 8U) | low);
}

uint8_t MPU6050_ReadRaw(MPU6050_Raw_t *raw)
{
    uint8_t buf[MPU6050_RAW_BYTES];
    if ((raw == NULL) ||
        (HAL_I2C_Mem_Read(&hi2c1, MPU6050_ADDR_HAL, MPU6050_REG_DATA_START,
                          MPU6050_REG_ADDR_SIZE, buf, sizeof(buf),
                          MPU6050_I2C_TIMEOUT_MS) != HAL_OK))
    {
        return 0U;
    }

    raw->accel_x = MPU6050_JoinSigned(buf[MPU_AX_H], buf[MPU_AX_L]);
    raw->accel_y = MPU6050_JoinSigned(buf[MPU_AY_H], buf[MPU_AY_L]);
    raw->accel_z = MPU6050_JoinSigned(buf[MPU_AZ_H], buf[MPU_AZ_L]);
    raw->gyro_x  = MPU6050_JoinSigned(buf[MPU_GX_H], buf[MPU_GX_L]);
    raw->gyro_y  = MPU6050_JoinSigned(buf[MPU_GY_H], buf[MPU_GY_L]);
    raw->gyro_z  = MPU6050_JoinSigned(buf[MPU_GZ_H], buf[MPU_GZ_L]);
    return 1U;
}

uint8_t id;
if (!MPU6050_ReadWhoAmI(&id) || !MPU6050_IdMatches(id) || !MPU6050_Wake())
{
    Debug_ReportMpuInitFailure(id, HAL_I2C_GetError(&hi2c1));
}
```

地址、WHO_AM_I 期望值、寄存器、字段下标、唤醒值和量程换算比例必须来自当前 MPU6050 手册/模块资料。姿态角需要独立的标定与融合算法，不能直接等于原始值。

## 调试方法

```text
确认地址 ACK 与 WHO_AM_I
-> 检查是否解除睡眠
-> 打印连续寄存器原始字节
-> 核对 int16_t 拼接和轴顺序
-> 静止/翻转观察原始六轴变化
-> 再检查量程与偏置
-> 最后调滤波和姿态融合
```

## 常见坑

| 现象 | 常见原因 | 处理方法 |
|---|---|---|
| ID 不对 | 地址/寄存器/左移错误 | 扫描并读单寄存器 |
| 原始值不变 | 未解除睡眠 | 检查电源管理配置 |
| 符号错误 | 高低字节/符号拼接错 | 打印单字节再组合 |
| 换算离谱 | 量程与比例不一致 | 按同一配置计算 |
| 姿态漂移 | 把原始值直接积分 | 需要校准和融合 |
