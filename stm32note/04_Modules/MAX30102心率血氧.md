# MAX30102 心率血氧

> 模块定位：学习带 FIFO 和算法库的复杂 I2C 传感器分层。
>
> 原始来源：[[12_I2C传感器]]。
---
## 本节目标

- 能从 I2C、FIFO、原始 PPG 波形到算法逐层验证。
- 能判断饱和、接触不良和 FIFO 错位等信号质量问题。
- 能说明算法库、参数和结果有效性为何必须单独核对。

## 核心概念

### 知识地图

| 名词 | 工程含义 |
|---|---|
| PPG | 光电容积脉搏波 |
| 红光/红外 | 不同波长的光学采样通道 |
| FIFO | 缓存连续采样结果 |
| LED 电流 | 影响光强、功耗和信号幅度 |
| 采样率/脉宽 | 影响时间分辨率、噪声和量程 |
| 算法有效性 | 心率/血氧输出需要质量判断 |

### 模块作用

采集红光/红外 PPG 原始波形，理解 FIFO、采样参数和算法有效性边界。

### 学习主线

```text
检测设备
-> 配置采样和 LED
-> 配置/读取 FIFO
-> 获得红光与红外原始波形
-> 验证信号质量
-> 调用算法库
-> 判断结果有效性
```

底层通信、原始数据和算法层必须分开调试。心率/血氧不是某个寄存器的直接读数，也不能作为医疗结论。

> 视频待核对：设备地址、ID、寄存器、FIFO 格式、LED/采样参数、算法库来源、样本数量、滤波和显示接口。

不能凭空补完整算法。

## 本质理解

MAX30102 通过 FIFO 提供红光和红外原始采样，心率与血氧不是可以直接读取的寄存器结果。必须先确认 FIFO 对齐、波形幅值和接触质量，再判断算法输出是否可信。

## 硬件连接关系

- 模块电源和逻辑电平按模块原理图
- I2C SCL/SDA 与共地
- INT 可用于 FIFO/数据就绪
- 手指接触和遮光结构影响信号质量

## 通信 / 控制链路

```text
确认地址/ID
-> 软件复位或基础初始化
-> 配置 LED/采样/FIFO
-> 等待数据
-> 读取红光/红外原始值
-> 画波形/检查饱和
-> 再接算法库
```

## CubeMX 配置要点

1. 启用 I2C
2. 可选 INT 配 EXTI
3. 串口用于输出 FIFO 原始值
4. 连续采样可设计双缓冲，但先阻塞读通

## 本模块依赖的 HAL 层

| 模块动作 | 依赖 HAL | 说明 |
|---|---|---|
| 探测设备地址 | `HAL_I2C_IsDeviceReady()` | 只确认 ACK，不证明 FIFO 和光学链路已工作 |
| 读取 ID、状态和 FIFO 字节 | `HAL_I2C_Mem_Read()` | 读取长度、FIFO 指针和样本格式必须按手册/驱动确认 |
| 写工作模式、LED 和采样配置 | `HAL_I2C_Mem_Write()` | 参数不能照抄未知项目；写入后检查返回值/必要时读回 |
| 响应数据就绪/中断脚 | `HAL_GPIO_EXTI_Callback()` | 可选；回调只记录事件，FIFO 读取放到主循环或任务 |
| 输出原始红光/红外值 | `HAL_UART_Transmit()` 或 `printf` | 先观察原始 PPG 波形，再调用算法 |

HAL 只负责 I2C/EXTI 字节链路。PPG 信号质量、FIFO 样本解释、心率/血氧算法、窗口和有效性判断不属于 HAL，必须查模块手册、算法来源和课程实测。

### 典型调用顺序

```text
MX_I2Cx_Init()
-> HAL_I2C_IsDeviceReady()
-> 读取 ID
-> 写最少采样/FIFO 配置
-> 读状态/FIFO 指针
-> 批量读取 FIFO 原始字节
-> 解码并打印红光/红外波形
-> 原始信号可靠后再接算法
```

### 什么时候用哪个函数？

| 场景 | 推荐函数 |
|---|---|
| 地址/ID 验证 | `IsDeviceReady()` + `Mem_Read()` |
| 写采样/FIFO 参数 | `HAL_I2C_Mem_Write()` |
| 读取连续 FIFO 数据 | 按手册确认长度后使用 `HAL_I2C_Mem_Read()` 或驱动封装 |
| INT 数据就绪 | EXTI 回调置标志，任务中读 FIFO |

## Bring-up 顺序

1. 确认供电、电平、I2C 上拉和设备 ACK。
2. 读取 Part ID，验证地址和寄存器访问。
3. 按已确认资料写入最少采样配置，并检查状态/FIFO 指针。
4. 按 FIFO 格式读取红光、红外原始样本。
5. 先观察波形幅值、饱和和接触质量，再接入算法。
6. 最后验证算法有效标志、显示和异常样本处理。

## 最小驱动框架

> 代码性质：示例框架，用于理解调用顺序，不能保证直接编译。

```c
typedef struct
{
    uint32_t red;
    uint32_t infrared;
} MAX30102_Sample_t;

static uint8_t MAX30102_IsOnline(void)
{
    return HAL_I2C_IsDeviceReady(&hi2c1, MAX30102_ADDR_HAL,
                                  MAX30102_READY_TRIALS,
                                  MAX30102_I2C_TIMEOUT_MS) == HAL_OK;
}

static uint8_t MAX30102_ReadPartId(uint8_t *part_id)
{
    return HAL_I2C_Mem_Read(&hi2c1, MAX30102_ADDR_HAL,
                             MAX30102_REG_PART_ID, MAX30102_REG_ADDR_SIZE,
                             part_id, 1U, MAX30102_I2C_TIMEOUT_MS) == HAL_OK;
}

static uint8_t MAX30102_ReadFifoBytes(uint8_t *data, uint16_t length)
{
    return HAL_I2C_Mem_Read(&hi2c1, MAX30102_ADDR_HAL,
                             MAX30102_REG_FIFO_DATA, MAX30102_REG_ADDR_SIZE,
                             data, length, MAX30102_I2C_TIMEOUT_MS) == HAL_OK;
}

uint8_t MAX30102_ReadSample(MAX30102_Sample_t *sample)
{
    uint8_t fifo[MAX30102_SAMPLE_BYTES];
    if ((sample == NULL) || !MAX30102_ReadFifoBytes(fifo, sizeof(fifo)))
    {
        return 0U;
    }
    return MAX30102_DecodeSample(fifo, sizeof(fifo), sample);
}

static uint8_t MAX30102_ProcessWindow(const MAX30102_Sample_t *samples,
                                      uint16_t count,
                                      MAX30102_Result_t *result)
{
    /* 算法实现和参数必须来自明确、可追溯的算法库。 */
    return MAX30102_Algorithm_Process(samples, count, result);
}

uint8_t part_id;
if (!MAX30102_IsOnline() ||
    !MAX30102_ReadPartId(&part_id) ||
    !MAX30102_PartIdMatches(part_id))
{
    Debug_ReportMax30102InitFailure(part_id, HAL_I2C_GetError(&hi2c1));
}
```

设备地址、Part ID、FIFO 寄存器、样本字节数、红光/红外拼接方式和算法库均为待核对项。示例只展示通信、原始样本与算法接口分层，不提供医疗结论。

## 调试方法

```text
确认 I2C ACK 与 Part ID
-> 检查配置写入和 FIFO 状态
-> 核对每个样本的字节数量
-> 绘制红光/红外原始波形
-> 排查饱和、错位和接触问题
-> 再检查算法输入窗口
-> 最后判断结果有效性
```

## 常见坑

| 现象 | 常见原因 | 处理方法 |
|---|---|---|
| I2C 通但无波形 | FIFO/模式未启动 | 检查状态和配置顺序 |
| 数据饱和 | LED 电流/接触不合适 | 观察原始幅值再调参数 |
| FIFO 错位 | 读取字节数/指针处理错 | 记录 FIFO 指针和原始字节 |
| 算法乱跳 | 原始信号质量差 | 先看 PPG 波形和有效标志 |
| 误作医疗结论 | 算法/校准不具医疗资质 | 仅作学习和趋势观察 |
