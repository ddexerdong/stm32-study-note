# 数字传感器与 LM393

> 模块定位：把光敏、反射、热敏、火焰等比较器模块统一为数字输入案例。
>
> 原始来源：[[02_GPIO与传感器]]、[[05_ADC模数转换]]。
---
## 本节目标

- 能用统一模型区分 LM393 模块的 DO 与 AO。
- 能先实测有效电平，再选择 GPIO 或 ADC 读取。
- 能按供电、阈值、原始信号和业务逻辑分层排错。

## 核心概念

### 知识地图

| 名词 | 工程含义 |
|---|---|
| LM393 | 双比较器，把传感电压与阈值比较 |
| DO | 比较后的数字输出 |
| AO | 连续模拟电压输出 |
| 阈值电位器 | 调整比较基准 |
| 有效电平 | 触发时 DO 是高还是低，需实测 |

### 模块作用

用比较器把连续传感信号转换成阈值型数字输入；同时保留 AO 供 ADC 观察连续变化。

### 通用结构

```text
传感元件产生模拟变化
-> 模块电位器设置比较阈值
-> LM393 输出 DO 高/低电平
-> STM32 GPIO 读取
-> 业务层控制 LED 或蜂鸣器
```

### DO 与 AO

- DO 只表示是否越过阈值，不代表连续物理量。
- AO 是模拟电压，应交给 [[ADC与模拟采样]]。
- 有效电平、阈值方向和模块供电不能凭模块名称猜测。

### 模块差异

| 模块 | 主要变量 | 特有风险 |
|---|---|---|
| 光敏 | 环境光 | 阈值和场景相关 |
| 反射 | 距离、表面颜色、环境光 | 输出容易抖动 |
| 热敏 | 温度变化 | 响应较慢，DO 不是温度值 |
| 火焰 | 特定光谱响应 | 只做低风险教学测试 |

## 本质理解

LM393 模块的 DO 是比较器对阈值的判断结果，只能表示“是否越界”，不能还原连续物理量；AO 才保留模拟变化。DO 的有效电平和阈值方向必须通过原理图或实测确认后再映射为业务状态。

## 硬件连接关系

- VCC/GND 按模块额定电压并与 STM32 共地
- DO 接普通 GPIO 输入
- AO 仅接支持 ADC 的 Analog 引脚
- LED/蜂鸣器由独立输出脚或驱动级控制

## 通信 / 控制链路

```text
确认供电/共地
-> 串口打印 DO
-> 调电位器观察翻转
-> 读取 AO 原始值
-> 建立 DO 有效电平
-> 再连接执行器业务
```

## CubeMX 配置要点

1. DO 配 GPIO_Input，按输出类型决定上拉/下拉
2. AO 配 ADC Analog
3. LED/蜂鸣器脚配 GPIO_Output 或 PWM
4. 先不用 EXTI，轮询验证有效电平

## 本模块依赖的 HAL 层

| 模块动作 | 依赖 HAL | 说明 |
|---|---|---|
| 读取比较器数字输出 DO | `HAL_GPIO_ReadPin()` | 先实测高/低有效；输入模式和上下拉按模块输出级选择 |
| 读取模拟输出 AO | `HAL_ADC_Start()` + `HAL_ADC_PollForConversion()` + `HAL_ADC_GetValue()` | 先确认输入范围和 ADC 校准；raw 不等于物理量 |
| 控制 LED/蜂鸣器等低速输出 | `HAL_GPIO_WritePin()` | 负载驱动能力和有效电平以原理图为准 |
| 消抖/持续触发判断 | `HAL_GetTick()` | 用非阻塞状态机，避免长 `HAL_Delay()` |

HAL 只读取 DO/AO 电气结果。阈值电位器、比较器极性、传感器响应和安全判断属于模块硬件与业务层。

### 典型调用顺序

```text
确认供电/共地
-> GPIO 读取 DO 并串口打印原始电平
-> ADC 轮询读取 AO raw
-> 调整阈值观察 DO/AO 关系
-> 最后接 LED/蜂鸣器业务
```

### 什么时候用哪个函数？

| 场景 | 推荐函数 |
|---|---|
| 只判断超过阈值 | `HAL_GPIO_ReadPin()` |
| 需要连续强弱趋势 | ADC 轮询或 `HAL_ADC_Start_DMA()` |
| 非阻塞告警保持/消抖 | `HAL_GetTick()` 状态机 |

## Bring-up 顺序

1. 确认模块供电、共地、DO/AO 接线和安全测试条件。
2. 只读取 DO 原始电平，同时观察模块比较器指示灯。
3. 缓慢调节输入或阈值，实测 DO 有效电平与翻转方向。
4. 若需要连续强度，再单独配置 ADC 读取 AO。
5. 建立 DO 业务状态或 AO 阈值，保留原始值日志。
6. 最后连接 LED、蜂鸣器等执行器。

## 最小驱动框架

> 代码性质：示例框架，用于理解调用顺序，不能保证直接编译。
> 验证状态：未上板验证，需按 CubeMX 变量名、开发板原理图和课程源码核对。

```c
typedef struct
{
    GPIO_PinState do_active_level;
    uint32_t last_ao_raw;
} DigitalSensor_t;

static uint8_t DigitalSensor_ReadDO(const DigitalSensor_t *sensor)
{
    GPIO_PinState level = HAL_GPIO_ReadPin(SENSOR_DO_GPIO_Port,
                                           SENSOR_DO_Pin);
    return level == sensor->do_active_level;
}

static uint8_t DigitalSensor_ReadAO(DigitalSensor_t *sensor)
{
    if (HAL_ADC_Start(&hadc1) != HAL_OK) return 0U;
    if (HAL_ADC_PollForConversion(&hadc1, ADC_TIMEOUT_MS) != HAL_OK) return 0U;

    sensor->last_ao_raw = HAL_ADC_GetValue(&hadc1);
    return 1U;
}

static void DigitalSensor_Task(DigitalSensor_t *sensor)
{
    uint8_t active = DigitalSensor_ReadDO(sensor);
    (void)DigitalSensor_ReadAO(sensor);

    HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin,
                      active ? LED_ON_LEVEL : LED_OFF_LEVEL);
    Debug_ReportSensor(active, sensor->last_ao_raw);
}

DigitalSensor_t sensor = {
    .do_active_level = SENSOR_DO_ACTIVE_LEVEL,
};

while (1)
{
    DigitalSensor_Task(&sensor);
    HAL_Delay(SENSOR_SAMPLE_INTERVAL_MS);
}
```

`SENSOR_DO_ACTIVE_LEVEL` 必须通过万用表/串口实测确认；AO 的电压范围、阈值含义和物理量换算见 [[ADC与模拟采样]]，不能由 LM393 数字输出直接推导。

## 调试方法

先打印 DO 原始电平，再决定是否取反；调节阈值时同时观察模块指示灯和 GPIO 读数。

> 视频待核对：课程模块型号、接线、有效电平、阈值方向和安全测试方式。

```text
确认安全测试条件与供电
-> 同时观察模块指示灯和 DO 电平
-> 调阈值确认翻转方向
-> 万用表/ADC 检查 AO 变化
-> 核对 GPIO 上下拉和 ADC 引脚
-> 再映射为业务状态
-> 最后连接执行器
```

## 常见坑

| 现象 | 常见原因 | 处理方法 |
|---|---|---|
| DO 一直不变 | 阈值不合适/接错 AO | 观察模块指示灯并调阈值 |
| 逻辑相反 | 有效电平猜错 | 串口打印并实测 |
| AO 读数异常 | 未配 Analog/超范围 | 核对 ADC 引脚和电压 |
| 误触发 | 阈值附近抖动 | 加迟滞/连续采样确认 |
| 火焰测试危险 | 使用真实明火 | 仅做低风险教学测试 |
