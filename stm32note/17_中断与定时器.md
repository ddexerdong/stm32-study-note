## [17] 系统定时器与中断闪灯

### 知识点
- SysTick 系统定时器
- STM32 中断的基本概念
- HAL 定时器中断的使用
- 中断优先级 NVIC
- `HAL_TIM_Base_Start` vs `HAL_TIM_Base_Start_IT`

### 关键原理

#### SysTick vs 通用定时器

| | SysTick | 通用定时器 TIM2/3/4 |
|--|---------|-------------------|
| 归属 | Cortex-M3 内核自带 | STM32 外设 |
| 用途 | HAL 时基（HAL_Delay/HAL_GetTick） | 用户定时、PWM、捕获 |
| 位数 | 24 位 | 16 位 |
| 优先级 | 默认最低（15） | 可配置 |

> SysTick 优先级最低是故意的——不能让它打断重要的用户中断。

#### 定时器工作原理

```
TIMx_CLK（定时器时钟）
    ↓ ÷ (PSC + 1)      ← 预分频：降速
计数时钟
    ↓ 每个时钟 CNT + 1
CNT 计数器
    ↓ CNT == ARR（溢出）→ 产生更新事件/中断
ARR 自动重载值
    └→ CNT 归零，循环
```

#### 定时时间公式 ⭐

```
T = (PSC + 1) × (ARR + 1) / TIMx_CLK

例：TIM2_CLK = 72MHz，定时 1 秒
PSC = 7199（分频后 72M/7200 = 10kHz）
ARR = 9999（10000 次 = 1 秒）
T = 7200 × 10000 / 72,000,000 = 1s ✓
```

#### 🔴 定时器时钟确认（头号坑）

APB1 分频 ≠ 1 时，定时器时钟 = PCLK1 × 2：

| 定时器 | 总线 | PCLK | 分频 | 定时器时钟 |
|--------|------|------|------|----------|
| TIM1 | APB2 | 72MHz | /1 | 72MHz |
| TIM2/3/4 | APB1 | 36MHz | /2（≠1→×2）| **72MHz** |

### CubeMX 配置步骤

1. Timers → TIM2 → Clock Source: Internal Clock
2. Prescaler = 7199, Counter Period = 9999（1 秒定时）
3. NVIC Settings → TIM2 global interrupt → Enable
4. 生成代码

### HAL 库代码模板

```c
// main() 中，while(1) 之前启动
HAL_TIM_Base_Start_IT(&htim2);  // 注意是 _IT 版本！

// 中断回调（放在 /* USER CODE BEGIN 4 */ 区域）
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM2)
    {
        HAL_GPIO_TogglePin(GPIOB, GPIO_PIN_0);  // 每秒翻转 LED
    }
}
```

### 🔴 中断里不能做的事

```c
// ❌ 绝对禁止在中断回调里：
HAL_Delay(100);           // 死锁！SysTick 优先级比 TIM 低，永远进不来
printf("xxx\r\n");        // 阻塞太久，中断堆积
while(某个条件);           // 可能永远等不到

// ✅ 正确做法：设标志位，让 main 循环去处理
volatile uint8_t flag = 0;  // volatile 重要！告诉编译器这个变量会被中断修改

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    flag = 1;  // 只设标志，快速退出
}

// while(1) 中：
if (flag)
{
    // 做耗时的事
    flag = 0;
}
```

> 为什么 `HAL_Delay` 会死锁？它等 SysTick 中断来计数，但 SysTick 优先级最低。如果你在优先级更高的 TIM 中断里调它，SysTick 永远进不来 → 永远等不到 → 卡死。

### 中断优先级 NVIC

```
数字越小 = 优先级越高

抢占优先级：高优先级的可以打断低优先级的中断
响应优先级：同抢占优先级时决定排队顺序
```

| 中断源 | 抢占优先级 | 原因 |
|--------|----------|------|
| SysTick | 15（最低） | 不能让时基打断重要中断 |
| UART | 1 | 串口数据不能丢 |
| TIM | 2 | 定时任务 |
| EXTI | 3 | 按键响应可以慢一点 |

### 易错点
- 定时时间算不准 → 没确认 TIMx_CLK（APB1 ×2 规则）
- 中断回调不触发 → 用了 `HAL_TIM_Base_Start` 而不是 `_Start_IT`
- 中断里卡死 → 调了 `HAL_Delay()`
- 标志位没用 `volatile` → 编译器优化导致 main 循环永远读不到变化

## [18] 外部中断应用与回调函数

### 知识点
- EXTI（External Interrupt）外部中断
- 三种触发方式
- GPIO EXTI 回调函数
- 中断里的软件消抖

### 关键原理

任何一个 GPIO 引脚都可以配置为外部中断源。引脚电平变化时，硬件自动进入中断处理函数。

#### 触发方式

| 方式 | 什么时候触发 | 典型场景 |
|------|------------|---------|
| 下降沿 Falling | 高→低的瞬间 | 按键按下（上拉输入时）⭐ |
| 上升沿 Rising | 低→高的瞬间 | 按键松开 |
| 双边沿 Both | 任意边沿 | 检测变化频率 |

### CubeMX 配置步骤

1. Pinout → 点目标引脚（如 PA0）→ 选 GPIO_EXTI0
2. System Core → GPIO → 该引脚 → GPIO mode: External Interrupt Mode with Falling edge
3. NVIC → EXTI line0 interrupt → Enable
4. 生成代码

### HAL 库代码模板

```c
// EXTI 回调（放在 /* USER CODE BEGIN 4 */ 区域）
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_0)
    {
        // 在中断里也要消抖！（用时间戳，不用 Delay）
        static uint32_t lastTime = 0;
        if (HAL_GetTick() - lastTime > 200)  // 200ms 防抖
        {
            lastTime = HAL_GetTick();
            HAL_GPIO_TogglePin(GPIOB, GPIO_PIN_0);
        }
    }
}
```

### 易错点
- EXTI 中断里同样不能调 `HAL_Delay`，用 `HAL_GetTick()` 做时间判断
- 机械按键在 EXTI 里也需要消抖（抖动同样会产生多次边沿触发）
- 不同引脚共用的 EXTI 线（如 PA0、PB0、PC0 都连 EXTI0）**同一时间只能有一个启用了 EXTI**，这是硬件限制
